# AI会話システム 仕様

## 位置づけ
- GAME_SPEC.mdでは、AI自由会話は「将来的な追加」（15章・17章）。Phase 6の完了後に、追加のPhase（Phase 7）として扱う。それまではAI接続部分を実装しない。
- ただし、会話方式を切り替える入口と、固定シナリオ・書く/話すの会話は、Phase 1〜2で作る。
- AI会話は任意の機能（ローカルAIを使う場合はPC限定）。ゲーム本体はAIなしで最後まで遊べること。
- 下記の評価で人間が合格と判断するまで、画面に「試験機能」と表示する。

## 開発PCの条件
- メモリ8GB、GPUはIntel HD Graphics 620（CPU内蔵）。Ollamaはほぼ CPU だけで動くことになり、速度にもメモリにも余裕がない。
- 検証は、Claude Code・Antigravity・開発サーバーを止めた状態で行う。
- このPCでローカルAIが実用にならない場合は、下記Bの外部無料枠と比べる。どちらも実用にならなければ、会話方式の切り替え口だけを残し、AI会話の正式採用は見送る。

## AIの接続先の候補（Phase 7で比較して決める）
- A. ローカル（Ollama）：無料で、APIキーが不要。会話の内容がPCの外に出ない。ただしこのPCでは遅く、小さいモデルしか動かない。
- B. 外部サービスの無料枠（例：Gemini API）：小さいローカルモデルより韓国語の質が高い見込み。ただし無料枠は回数制限が厳しく、予告なく変わることがある。無料枠では、送った内容がサービスの改善に使われることがある。
  - APIキーは利用者が自分で取得し、設定画面で入力する。コードやリポジトリには書かない。
  - ブラウザから直接呼べるか、回数制限の中で会話練習として成り立つかを、Phase 7の最初に確認する。
- AとBは同じ評価方法（下記）で比べ、どれを採用するかは人間が決める。
- 有料プランは使わない。

## 会話の3つの方式
| 方式 | 内容 | 必要なもの |
|---|---|---|
| 固定シナリオ | 用意した台本と選択肢で進む | なし |
| 自由入力 | プレイヤーの入力を登録済みの正解と照合 | なし |
| AI会話 | AIが返答・訂正する（接続先は上記のAかB） | AかBの準備 |

- 3つの方式は共通の入口で切り替えられるようにする（src/learning/conversation/）。
- AIが使えないときは、自動で自由入力または固定シナリオに切り替え、理由を画面に表示する。

## 接続
- ローカルAI（A）の接続先は http://localhost:11434 または http://127.0.0.1:11434 のみ。
- 外部サービス（B）に接続するのは、利用者が設定でBを選び、APIキーを入力した場合だけ。それ以外の外部サーバーには接続しない。
- 設定画面に「AI会話を使う」スイッチ、モデル選択、接続テストボタンを置く。初期値はオフ。オフのときはAIへの通信を一切しない。
- 接続失敗、モデル未導入、時間切れのそれぞれで、日本語で原因と対処を表示する。CPUだけで動かすと返答に時間がかかるため、時間切れは長めにし、待っている間は「考え中」と表示する。
- Ollamaの導入やモデルのダウンロードをゲームから実行しない。手順は docs/OLLAMA_SETUP.md に書く。
- ゲームをlocalhost以外（公開URL）で開く場合、Ollamaの環境変数 OLLAMA_ORIGINS にそのURLを追加しないと接続できない。この手順も OLLAMA_SETUP.md に書く。

## Aで比較するモデル（メモリ8GBで動く大きさ）
- qwen3:1.7b（第一候補。思考モードはオフにして使う）
- exaone3.5:2.4b（LGの韓国語に強いモデル。ライセンスは非商用）
- qwen3:0.6b（下限の参考として）
- qwen3:4b（メモリに余裕があれば上限の参考として。重すぎる場合は中止）

動かせなかった候補は「未検証」として理由とともに記録する。

## 評価方法
- docs/ai-eval/test-cases.json に評価用の入力を20件用意する。
  - 正しい文：10件（訂正してはいけない）
  - 日本語話者がよく間違える文：10件（助詞 은/는・이/가、을/를、活用、敬語のレベルなど）
  - 各件に「期待する訂正」を書いておく。期待値はAIに作らせず、教材や文法書など信頼できる情報源で確認する。
- 評価スクリプトで全モデルに同じ入力を送り、結果を docs/ai-eval/results.md に表で記録する。
- 評価項目
  1. 正しい文を誤って訂正した件数（最重要。0件が目標）
  2. 誤りを正しく指摘できた件数
  3. 指定の形式（JSON）で返せなかった件数
  4. 平均応答時間（このPCでは特に重要。会話として待てる長さか）
  5. 返答が短く（2文以内）収まったか
- どのモデルを採用するか、合格とするかは、結果を見て人間が決める。

## AIへの指示（システムプロンプト）
- コードに直接書かず、src/learning/conversation/prompts/ にキャラクターごとのファイルで置く。
- 含める内容：キャラクターの性格と口調、プレイヤーのレベル、既習の単語と文法（多い場合は直近のもの）、「返答は韓国語で2文以内」「誤りは優しく指摘する」「会話を一方的に終わらせず質問を返す」。

## AIの出力形式
Ollamaの format 指定（Bでは各サービスのJSON出力の指定）で、次の形のJSONを返させる。

```json
{
  "reply_ko": "韓国語の返答",
  "reply_ja": "日本語訳",
  "corrections": [
    { "original": "プレイヤーの表現", "corrected": "自然な表現", "explanation_ja": "短い説明" }
  ]
}
```

JSONとして読めない場合は返答だけを表示し、訂正は出さない。

## 学習記録
- 会話終了時に保存する：会話ログ、使った単語、AIの訂正、復習候補。
- 「使った単語」は、プログラムで教材データと照合して判定する（AIに判定させない）。
- AIの訂正は「AIによる提案」として保存し、教材データの正解とは区別する。
- 復習候補 ＝ 訂正を受けた表現 ＋ 自由入力で間違えた問題。

## 表示
- AIの訂正には「AIによる提案です。誤りを含むことがあります」と添える。
- AIの返答は文字として表示し、HTMLとして解釈しない。
