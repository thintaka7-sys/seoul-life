## 2. これまでに決めたこと（仕様書などに書いていないもの）

### 進め方・やり取り
- 人間の依頼は日本語。報告も日本語で、CLAUDE.md の報告の書式に従う。
- 計画の「仕様の不明点」は Q1, Q2… と番号を付け、選択肢と推奨案を出す。返事は「推奨どおり」＋追加の指示、という形で来ることが多い。
- 利用上限などで途中で止まる場合は、作業の順番のどこまで終わったかを報告してから止まる。
- 依頼の中で「ここまで終わったら報告」と区切りを指定されることがある。そのときは区切りでコミットして報告し、指示どおり先へ進む。Phase 3 は3回の区切り（教材の形 → 物語の仕組み → 学習の仕組みと仕上げ）で進めた。
- 人間は、スマホでの確認の結果を「1〜n の番号つきのお願い」で送ってくる。「できたら報告」と「計画をください」が混ざることがあるので、どちらかを読み分ける（計画を求められた項目は、承認まで実装しない）。
- 原因が分からない不具合は、推測で直す前に「原因の見立て・直し方の案・人間が確かめる手順」を短く報告して止まる（2026-11-25 のマナーモードの件で、人間がこの進め方を求めた）。
- コミットは、このリポジトリだけの設定で user.name `thintaka7-sys`、メールは GitHub の noreply アドレス（`git config user.email` で確認）。本名・個人のメールアドレスをコミットや外部への送信に入れない。
- コミットメッセージは日本語で、最後に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` を付ける。

  - **スマホでは、指が触れた瞬間（pointerdown）は「音を出してよい操作」と認められないことがある**（BUG-002）。準備は pointerup・touchend・click でも行い、止まったら次の操作で再開する。「操作の最中」かは `navigator.userActivation.isActive` で確かめ、操作の外では音の部品を作らない（ブラウザの警告が出るため）。

- グリッドの列やキーボードの幅は、中身の文字の幅で広がらないよう `minmax(0, 1fr)`・`min-width: 0` にする（BUG-005）。
- 日本語訳の設定（いつも表示／タップで表示／表示しない）は、台詞・反応・ログ・単語カードの例文・コラムの韓国語にだけ効く。**選択肢には訳を出さない**（Q8 の C）。読み物の本文の訳は、問題に答え終わるまで出さない。
- 答え方（選ぶ・書く・話す）は、選んだものを、ゲームを開いている間は会話をまたいで覚える（保存しない。Q9 の C）。その往復で使えなければ、話す → 書く → 選ぶ の順で使えるものにする。
- 話して答える：
  - 正解は「書いて正解」と同じ記録・経験値。「声に出して言ってみる」（選んだ後の練習）には記録・経験値を付けない（Q10）。
  - 音声入力の初期値はオン。初めて使うときに説明を出し、「使わない」で設定をオフにする（Q11）。
  - 判定は `judgeSpoken`。候補のどれかが正解なら正解、分かち書きの違いは注意なし、数の言葉は数字でも正解（Q12）。同じ音の母音（ㅐ＝ㅔ、ㅒ＝ㅖ、ㅙ＝ㅚ＝ㅞ）と、文の頭・終わりのつなぎの声（음・어・으）はゆるめる（BUG-004 の Q1 の A）。**1字違いを許すような似ている度合いの判定は入れない**（안녕히 가세요／계세요 を通してしまうため）。
  - 聞き取りは、終わるまで待って区切りをつなぐ（iPhone は途中の結果が先に届く）。押した直後は「準備中」、マイクが動き出してから「どうぞ」と出す。
- カフェの注文（GAME_SPEC 4-4）：書く・話すで注文し、数・語尾・前に付ける言葉・別表記を認める。店員は教材の台詞で反応する。施設から何度でも注文し直せる。「答えの例を見る」で進んだときは、注文できた記録・経験値を付けない。
- 小テストは8問・80点で合格。全レッスンを最初から選べる（Q2・Q3）。聞かせるのは音節と単語だけ（字母を読み上げると字母の名前で読まれるため。Q4）。
- **検索サイトに載せない**：`index.html` に `<meta name="robots" content="noindex, nofollow">` を入れている（人間の指示、2026-11-20）。robots.txt は使わない。GitHub のリポジトリ自体は公開のまま。

### iPhone のマナーモードとマイク（Phase 3。GAME_SPEC 10-4）
- 仕組みは `src/audio/audioSession.ts` の先頭のコメントにまとめてある。要点：
  - ふだんは `navigator.audioSession.type` を `ambient`（マナーモードでは BGM・効果音が鳴らない）。読み上げの間だけ `playback`（学習に必要なので鳴らす）。
  - **`playback` の間に流し始めた音は、`ambient` に戻した後もマナーモードで鳴ってしまう。** そのため読み上げの間は BGM を止め、音の出口（AudioContext）も止め、どの道筋でも流し始めない。BGM・AudioContext を動かすのは、必ず `isSilentModeUnsafe()`・`canStartAudio()` を確かめる道筋を通す。
  - 同じ値を入れ直してもブラウザは何もしないので、「かけ直し」は `auto` → `ambient` の順に入れる。起動時・マイクを閉じた後に行う。
  - マイクで聞くと iPhone は `play-and-record` になる。聞いている間は BGM・効果音を止め、閉じたらかけ直して 0.3 秒待ってから戻す。
- **Safari がマイクを開いたままにすることがあり、ページからは閉じきれない**（stop・abort しかなく、MediaStream がないため）。そのあいだはマナーモードが効かない。対策は2つ：
  - 設定「話して答えたあと、BGM・効果音を止める」（設定 v6 の `quietAfterVoiceInput`）。`navigator.audioSession` がある端末（iPhone）では最初からオン。オンなら、そのページで一度マイクを使った後は、開き直すまで BGM・効果音を止める（読み上げは鳴る）。
  - 聞き取りが終わったら、知らせを外して `abort()` をもう一度呼ぶ（`recognition.ts` の `release()`）。これで iPhone のマイク使用中の表示（オレンジの点）が消えるようになった（人間が確認、2026-11-25）。
- 2026-11-25 に「ページを開いた最初からマナーモードで鳴る」という報告があったが、Safari を終わらせて開き直す・プライベートタブ・マイクを使った後に開き直す、のどれでも再現しなかった。前の版でマイクが開いたまま（オレンジの点が残ったまま）新しい版を開いたためと見て、起動時の処理は変えていない（人間の判断）。また起きたら、下の `?debug=audio` の記録をもらう。
- **音の記録（開発者向け）**：URL の末尾に `?debug=audio` を付けたときだけ、画面の下に記録の欄を出す（`src/audio/audioDebug.ts`・`src/components/AudioDebugPanel.tsx`。ふだんは何も記録しない）。見方：
  - 正常：たたんだ欄が「ambient 以外で鳴らした：0件」。BGM・効果音・音の出口の行が、どれも `type=ambient`。
  - ゲームの問題：「!!」の付いた赤い行が出る（ambient でない扱いのまま音を流し始めた）。
  - Safari 側の問題：赤い行が0件なのにマナーモードで鳴る（ページの指定は ambient でも、Safari が別の扱いを使っている）。
  - 新しく音を流し始める道筋を作ったら、`logAudio(…, true)` で記録を付ける。
- 画面が見えなくなったら（別のタブ・ホーム画面）、BGM・効果音・読み上げ・マイクの聞き取りを止め、戻ったら BGM を続きから流す（`src/audio/pageVisibility.ts`）。

### BGM と音素材（Phase 3）
- BGM は `npm run audio`（ffmpeg）で、フェードアウトの手前で切り、音の大きさをそろえて 128kbps の MP3 にする（`scripts/audio/`）。元の音（`assets-inbox/audio/`）は git に入れない。
- 再生は `src/audio/bgm.ts`：2つの audio 要素を重ねて切り替え、Web Audio のつまみで音量を変える（iPhone は `audio.volume` が効かないため）。学習画面は小さめ、読み上げの間はさらに小さく、マイクで聞いている間は消す。場所・場面ごとの曲は `src/app/bgmScene.ts` と施設の `bgm`。
- 場面の効果音は CC0 の6つ（door_bell・cup・buzzer・page・car_door・call）。飛行機の音は使える素材がなく、鳴らしていない。素材の一覧は docs/SOUND_GUIDE.md 4章。

### 復習と練習（Phase 2.5）
- 計画の Q1〜Q13 は推奨どおり。ただし (1) 音の変化の小テストに足したのは「カタカナの読みを選ぶ」「聞いてつづりを選ぶ」の2つだけ、(2) ドリルの問題にも `alternatives`、(3) 日本語を見て韓国語で書く数字の問題は、数字（3500 など）では正解にしない。
- 復習に入るもの：覚えた単語・文法、正解した会話の往復（学んだ翌日から）、間違えたドリルの問題、テストで間違えた問題、見かけた単語（「覚える」を押したもの）、形が変わる言葉（`form:`）。「答えを見る」で進んだ往復は「間違えた」として入る（経験値なし）。ハングルのレッスン・リスニング・読み物は入れない。
- 間隔は 1→3→7→14→30 日、間違えたら翌日。14日の間隔で正解したら「覚えた」。1日の上限20問。日付は端末の日付（`YYYY-MM-DD`）。
- 「練習」（期限前でも自由に）は経験値なし。間違えたときだけ翌日の復習に戻す。
- 経験値：期限の来た復習に正解3、ドリルの問題に初めて正解2、章末テストに初めて合格30。スタンプには付けない（ごほうびは Phase 4）。
- スタンプは `balance.stampActivities` のどれか1つを終えたら押す（今日の復習・ドリル・章末テスト・ハングルのレッスン合格・リスニング・イベント・聞き分け）。
- 章末テストは、その章の会話の「問題の往復」にすべて答えると受けられる。受けられないときも開けて、残っている会話と「遊ぶ」ボタンを出す（BUG-007）。
- 問題の形は1回分ごとに、形と問題の組み合わせを先に決める（`buildQuestions` の二部マッチング）。並べ替えを最優先する（BUG-009）。
- 同じ意味（日本語の意味が同じ）の言葉は、選択肢の不正解に使わず、書く問題では正解として認める。
- 会話の選択の往復（`kind: "decision"`）は、経験値・記録・復習なし。
- 学習画面の「会話をもう一度」と、施設の「もう一度遊ぶ」では、問題の往復の答えを記録・復習に入れる。経験値は、往復と答え方ごとに初めて正解したときだけ（BUG-007 の Q1 の A）。
- 図鑑：ジャンル（11種類）、習得状況（すべて／復習中／覚えた／見かけた）、品詞で絞り込む。表示名は `types.ts` の `GENRE_LABELS`・`PART_OF_SPEECH_LABELS`。形が変わる言葉は、元の形とよく出る形を図で並べる。

### 答えた後の見せ方（Phase 2.6。GAME_SPEC 4-0）
- 選ぶ問題は「✗ あなたの答え」「✓ 正解」「✓ あなたの答え（正解）」の印（`learning/feedback/missed.ts`、部品は `components/practice/AnswerFeedback.tsx`）。色だけに頼らない。

- 会話：書き直しの間は自分の答えだけを出す。会話の最後に、間違えた往復があるときだけ「ふり返り」（保存しない）。

### 聞き分け（Phase 2.6。GAME_SPEC 4-10）

### 「ゆっくり」の読み上げ（BUG-010。GAME_SPEC 10-4）

## 3. 作業の手順と注意点

### 画像の取り込み（`npm run assets`）
1. 人間が `assets-inbox/` に PNG か JPEG を置く（ファイル名は docs/ART_GUIDE.md の5章）。同じ名前が複数あれば新しいほうを使う。
2. `scripts/assets/assets.config.json` に、何として使うかを書く（`characters`／`backgrounds`／`map`／`cg`（一枚絵）／`cellSheets`（1枚を枠ごとに切り分けるもの。メニューの品物の絵・説明の図の絵））。
3. `npm run assets` を実行する。`public/assets/` に WebP、`src/data/assets/manifest.json` に一覧ができる（`?v=ハッシュ` 付き）。
4. 目で確かめる。立ち絵の透過は `npm run assets -- --preview <フォルダ>` で確かめられる。
5. WebP と manifest.json をコミットする。

注意：
- 立ち絵は「表情を横に並べた1枚の画像」から作る。人物どうしの間に背景だけの縦のすき間が必要。体の中心（下15%）でそろえている。
- 이수진 のかんざしの葉は緑なので、`keepGreen`（元の画像の画素の位置）で守っている。**表情の画像を作り直したら、この数値も直す。**
- 加工のしきい値は `scripts/assets/imageOps.ts`。テストは `imageOps.test.ts`。

### 音の取り込み（`npm run audio`）
- 元の音を `assets-inbox/audio/` に置き、`scripts/audio/audio.config.json` に書いて `npm run audio`。`public/audio/` に MP3、`src/data/assets/audio.json` に一覧ができる。素材の名前・入手先・ライセンスは docs/SOUND_GUIDE.md の一覧に足す。

### 背景IDの追加のしかた
- **施設の背景**（例：コンビニ）：`assets.config.json` の `backgrounds` に `{ "id": "convenience_store", "file": "bg_convenience_store.png" }` を足して `npm run assets`。IDは施設IDと同じにする。
- **場面の背景**（例：玄関。施設ではないもの）：
  1. `src/data/types.ts` の `SCENE_BACKGROUNDS` にIDを足す
  2. docs/CONTENT_FORMAT.md の 10-7 の表に行を足す（足さないとテストが失敗する）
  3. `assets.config.json` の `backgrounds` に足して `npm run assets`
- イベントでは `{ "type": "background", "id": "…" }`、おはなしでは場面（`scene`）で切り替える。画像がない間は施設の背景のまま進む。

### セーブデータの移行（形式を変えるとき）
形式の変更は**必ず先に確認を取る**（CLAUDE.md）。承認後の手順：
1. `src/storage/saveData.ts`：`CURRENT_SAVE_VERSION` を上げ、新しい型（`SaveDataV7` など）と検証を足す。
2. `src/storage/migrations.ts`：`MIGRATIONS[6]`（v6→v7）を足す。古い移行は消さない（v1 からでも順に移行できるようにする）。
3. 移行のテストを書く（`src/storage/*.test.ts`）。読み込めないデータは退避（`seoul-life:save-backup:<日時>:corrupt`）してから新規開始を選べる仕組みがすでにある。
4. 設定（`src/storage/settings.ts`）も同じ考え方で、version を上げて古い版から移す。端末によって初期値が違う項目は、`defaultSettings(options)` に端末の情報（`prefersReducedMotion`・`hasAudioSession`）を渡して決める（`src/app/boot.ts`）。
5. `scripts/e2e/browser.mjs` の `SAVE_VERSION` と `FAST_SETTINGS`（version と新しい項目）、`old-saves.mjs` の期待する版を上げる。chapters・phase26 なども設定の版を確かめているので、`grep -rn "version" scripts/e2e` で探して直す。
- 教材が変わって、セーブデータの「途中のイベントの段階の番号」がずれた場合は、範囲に収めて再開する（`resumeStep`。5章）。

### ブラウザでの確認（`scripts/e2e/`）
- 使い方と各スクリプトの中身・件数は `scripts/e2e/README.md`。`npm run build` → `npm run preview` → `node scripts/e2e/chapters.mjs http://localhost:4173/seoul-life/`。公開URLでも同じように動かせる。
- 8本：chapters（第1〜3章を通して遊ぶ。旧 first-day）・phase3（読み物・注文・図・形が変わる言葉など）・silent-mode（マナーモード・マイク・`?debug=audio`）・phase2・phase25・phase26・screens・old-saves、と共通の部品 browser.mjs・practice-answers.mjs。
- ヘッドレスの Edge（なければ Chrome）を使う。追加のパッケージは不要。
- **ヘッドレスでは音が聞けず、韓国語の音声もない**。読み上げ・音声認識・`navigator.audioSession` は偽物を入れて流れを確かめる（phase2・phase26・silent-mode）。実際の音・認識のよさ・マナーモードの効き方は、報告で「未確認」に入れる。
- 効果音は、ブラウザを「操作の前は音を出さない」設定で起動し、本物のマウス・指の操作（`Input.dispatchMouseEvent`・`dispatchTouchEvent`）で確かめる。
- 重ねて出す板は `main` の外（`#overlay-root`）にあるので、`mainText()` では読めない。
- 日付をずらす確認：localStorage の `e2e:dayOffset`（日数）。
- はみ出しの確認：`phase25.mjs` の `fitsCheck`（幅320・360・390px）。
- 起動時に Edge のプロフィールのフォルダで `EPERM` が出たら、前のヘッドレスの Edge が残っている。コマンドラインにプロフィールの場所を含む msedge を止め、数秒待ってから流し直す（別のプロフィール名で開いてもよい）。
- `viewport(幅, 高さ, mobile)` の3つ目を忘れない（スマホの幅で確かめるとき）。
- **偽の読み上げ（`phase26.mjs`）**：localStorage の `e2e:noSpeech`・`e2e:rateStrength`・`e2e:latency`・`e2e:elapsed` で端末の性質を変えられる。
- **偽の audioSession（`silent-mode.mjs`）**：`e2e:sessionType` で、開いたときの値を決められる（前のページの値が残っている端末をまねる）。
- **確認の前に、必ずビルドし直す**（`npm run preview` は `dist/` を出すだけ）。
- phase2 の「話す：途中の結果を『聞こえた言葉』として出す」は、まれに1件落ちる。流し直せば通る。
- 教材を変えたら、chapters.mjs の教材に合わせた部分を直す（多くは教材から値を読むようにしてある）。
- 画面の下に固定して出すもの（`?debug=audio` の欄など）は、e2e のクリックを横取りすることがある。

### Windows での作業の注意
- 作業ツリーのファイルが CRLF になっていることがある。完全一致で書き換える前に、`sed -i 's/\r$//'` で LF にそろえる。
- 書き換えの小さなスクリプトは Python で書き、`python -I` で動かす。韓国語を `print` すると cp932 でエラーになるので、出さない（出すなら `sys.stdout.buffer` に UTF-8 で）。

### 公開までの流れ（毎回）
1. `npm run typecheck` / `npm run lint` / `npm run test` / `npm run build` がすべて通る
2. `npm run preview` で `scripts/e2e/` を流す
3. コミット → `git push origin main`
4. GitHub API で Actions の完了（conclusion: success）を確かめ、公開URLでも `scripts/e2e/` を流す
