### 教材まわり
- **日本語の文（案内文・目標・コラムの文・プロフィールなど）にはハングルを入れない。** 韓国語が必要なら教材として依頼する。検証（`japaneseText`）でもエラーにしている。
- 教材は別のチャット（Claude）で作られ、ChatGPT などで確認されてから `content-inbox/<phase>/` に届く。届いたら `src/data/` の同じ名前のファイルと置き換え、組み込み後に content-inbox を削除する（content-inbox は git に入れていない）。
- イベントの下書きも教材側が作る。そのため、イベントの書き方は CONTENT_FORMAT.md に載せ、見本が検証を通ることをテストで保証している（`contentFormatDoc.test.ts`。キーの一覧と見出しも照合しているので、型を変えたら文書も直す）。
- 会話を作り直すときは新しいIDにし、古いIDは再利用しない（例：home_001 → home_003）。古い会話の記録はセーブデータに残ってよい（参照されないだけ）。
- キャラクターの名前の読みは、韓国語に合わせて空白なし（한지훈＝ハンジフン、이수진＝イスジン）。
- 店員・近所の住人のプロフィール文とテーマカラー（#D69C5E、#F6AD94）は、Claude Code が ART_GUIDE の案と画像から作った。人間が確認済み（2026-11-20、このままで可）。
- Phase 1 で決めた単語の割り当ての考え方：1度に覚える単語は5〜7語まで。多いときは場面を分ける。
- ハングルのレッスンは12本（Phase 2 の Q6）。有声音化は子音のレッスン3・4に入れ、音の変化は (1) 連音化・ㅎの弱化・激音化、(2) 鼻音化・濃音化・口蓋音化。流音化は後回し。二重パッチムは概要と、よく出るもの3〜4個だけ（Q5）。
- パッチムのレッスンより前のレッスンでは、パッチムのある単語を検証でエラーにする（`checkHangulCurriculum`）。読む練習の単語数は目安4〜8語で、下限は厳しくしない。
- リスニングは「聞いて単語を選ぶ」「会話を聞いて返事を選ぶ」を既存の教材から自動で作り、「聞いて文を選ぶ」だけを教材（`ListeningSentence`）にしている（Q7）。
- **「はい」を「예」と聞き取られる件**：예 は正しい言い方なので、Phase 2.5 で会話の問題を作り直すときに、教材担当が alternatives に加える（人間の決定）。
- docs/MATERIALS_HANDOFF.md（教材側への引き継ぎ）は、PCのフォルダの場所などが載っているので **git に入れない**（リポジトリは公開されているため）。作業ツリーに置いたままにする。
- 教材の置き場所 `content-inbox/`・`content-drafts/` は git に入れない。組み込んだら削除する。

### 画面・遊び方
- 画面遷移はルーターを使わず `useReducer`（`src/app/gameState.ts`）。Android の「戻る」は履歴に印を積んで、画面内の「戻る」と同じ動きにしている（`App.tsx` の `useBrowserBack`）。
- 縦画面が基本。PC では中央に1列で表示する。
- ゲーム内キーボードのキーは、幅が44pxに届かない（2ボル式で1段10キー）。高さを48pxにし、すき間なく並べることで例外として認めてもらった。
- フリガナは「おすすめ」（第3章まではいつも表示、その後はタップで表示）が初期値。タップは文ごと。選択肢は押すと答えになるので、横に「読み」ボタンを置いている。
- 表情の自動切り替え：正解の後の反応は笑顔、間違いへの反応は困り顔、「答えを見る」の後とそれ以外はふつう。**台詞や反応に `expression` が書いてあれば、そちらを優先する**（人間の指示）。
- マップ画面では、マップの絵を背景に敷かない（二重に見えるため。GAME_SPEC 6-1）。タイトル画面には敷く。
- 背景の切り替えはイベントの段階 `background` で行う（会話ごとに指定すると、単語の学習をはさむたびに部屋と玄関を行き来してしまうため）。Phase 3 の「おはなし」の場面の切り替えにも使う前提。
- 効果音は素材ファイルを使わず Web Audio API で作る（`src/audio/sfx.ts` のレシピ）。最初の操作まで鳴らさない。
  - **スマホでは、指が触れた瞬間（pointerdown）は「音を出してよい操作」と認められないことがある**（BUG-002）。準備は pointerup・touchend・click でも行い、止まったら次の操作で再開する。「操作の最中」かは `navigator.userActivation.isActive` で確かめ、操作の外では音の部品を作らない（ブラウザの警告が出るため）。
- **画面全体に重ねる板は、必ず `src/components/Overlay.tsx` を使う**（`#overlay-root` に出す）。`.panel` などの「ぼかし」（`backdrop-filter`）の中に `position: fixed` の要素を置くと、画面ではなくその板が基準になり、はみ出す（BUG-003）。
- グリッドの列やキーボードの幅は、中身の文字の幅で広がらないよう `minmax(0, 1fr)`・`min-width: 0` にする（BUG-005。ゲーム内キーボードは幅320pxまで確かめている）。
- 日本語訳の設定（いつも表示／タップで表示／表示しない）は、台詞・反応・ログ・単語カードの例文・コラムの韓国語にだけ効く。**選択肢には訳を出さない**（Q8 の C）。
- 答え方（選ぶ・書く・話す）は、選んだものを、ゲームを開いている間は会話をまたいで覚える（保存しない。Q9 の C）。その往復で使えなければ、話す → 書く → 選ぶ の順で使えるものにする。
- 話して答える：
  - 正解は「書いて正解」と同じ記録・経験値。「声に出して言ってみる」（選んだ後の練習）には記録・経験値を付けない（Q10）。
  - 音声入力の初期値はオン。初めて使うときに説明を出し、「使わない」で設定をオフにする（Q11）。
  - 判定は `judgeSpoken`。候補のどれかが正解なら正解、分かち書きの違いは注意なし、数の言葉は数字でも正解（Q12）。同じ音の母音（ㅐ＝ㅔ、ㅒ＝ㅖ、ㅙ＝ㅚ＝ㅞ）と、文の頭・終わりのつなぎの声（음・어・으）はゆるめる（BUG-004 の Q1 の A）。**1字違いを許すような似ている度合いの判定は入れない**（안녕히 가세요／계세요 を通してしまうため）。
  - 聞き取りは、終わるまで待って区切りをつなぐ（iPhone は途中の結果が先に届く）。押した直後は「準備中」、マイクが動き出してから「どうぞ」と出す。
- 小テストは8問・80点で合格。全レッスンを最初から選べる（Q2・Q3）。聞かせるのは音節と単語だけ（字母を読み上げると字母の名前で読まれるため。Q4）。
- **検索サイトに載せない**：自分と知り合いだけで遊ぶゲームなので、`index.html` に `<meta name="robots" content="noindex, nofollow">` を入れている（人間の指示、2026-11-20）。robots.txt は使わない（GitHub Pages のサブフォルダでは効かないうえ、クロールを止めると noindex が読まれないため）。ただし GitHub のリポジトリ自体は公開のまま。
- 演出の初期値は、端末の「動きを減らす」がオンなら「控えめ」。
- 経験値は「初めてのときだけ」付ける。会話は往復ごと・答え方（選ぶ／書く）ごとに1回ずつ。数値は `src/data/game/balance.json`（単語2、選ぶ10、書く15、イベント20）。

### 技術
- 追加したパッケージ：es-hangul（ハングルの組み立て、Phase 1）、sharp（画像の加工。開発用のみ、Phase 1.5）。ほかは追加していない（音声認識の型は `src/audio/recognition.ts` で自前で定義）。追加するときは必ず確認を取る。

- 元の画像（PNG）は git に入れない（`assets-inbox/*.png` を除外）。加工した WebP と一覧（manifest.json）だけをコミットする。

## 3. 作業の手順と注意点

### 画像の取り込み（`npm run assets`）
1. 人間が `assets-inbox/` に PNG を置く（ファイル名は docs/ART_GUIDE.md の5章）。
2. `scripts/assets/assets.config.json` に、何として使うかを書く（`characters`／`backgrounds`／`map`）。
3. `npm run assets` を実行する。`public/assets/` に WebP、`src/data/assets/manifest.json` に一覧ができる（`?v=ハッシュ` 付きなので、差し替えてもブラウザに古い画像が残らない）。
4. 目で確かめる。立ち絵の透過は `npm run assets -- --preview <フォルダ>` で、目立つ色の上に重ねた確認用の画像を出せる。
5. WebP と manifest.json をコミットする。

注意：
- 立ち絵は「表情を横に並べた1枚の画像」から作る。人物どうしの間に背景だけの縦のすき間が必要。表情を変えても体の位置が動かないよう、体の中心（下15%）でそろえている。
- 이수진 のかんざしの葉は緑なので、`keepGreen`（元の画像の画素の位置）で守っている。**表情の画像を作り直したら、この数値も直す。**
- 加工のしきい値（hard 90・soft 170・閉じた部分 75 など）は `scripts/assets/imageOps.ts`。テストは `imageOps.test.ts`。

### 背景IDの追加のしかた
- **施設の背景**（例：コンビニ）：`assets.config.json` の `backgrounds` に `{ "id": "convenience_store", "file": "bg_convenience_store.png" }` を足して `npm run assets`。IDは施設IDと同じにする。
- **場面の背景**（例：玄関。施設ではないもの）：
  1. `src/data/types.ts` の `SCENE_BACKGROUNDS` にIDを足す
  2. docs/CONTENT_FORMAT.md の 10-7 の表に行を足す（足さないとテストが失敗する）
  3. `assets.config.json` の `backgrounds` に足して `npm run assets`
- イベントでは `{ "type": "background", "id": "…" }` で切り替える。画像がない間は施設の背景のまま進む。

### セーブデータの移行（形式を変えるとき）
形式の変更は**必ず先に確認を取る**（CLAUDE.md）。承認後の手順：
1. `src/storage/saveData.ts`：`CURRENT_SAVE_VERSION` を上げ、新しい型（`SaveDataV4` など）と検証を足す。
2. `src/storage/migrations.ts`：`MIGRATIONS[4]`（v4→v5）を足す（v3→v4 は Phase 2 で追加済み）。古い移行は消さない（v1 からでも順に移行できるようにする）。
3. 移行のテストを書く（`src/storage/*.test.ts`）。読み込めないデータは退避（`seoul-life:save-backup:<日時>:corrupt`）してから新規開始を選べる仕組みがすでにある。
4. 設定（`src/storage/settings.ts`）も同じ考え方で、version を上げて古い版から移す（v1→v2・v2→v3 は足りない項目を初期値で埋めた）。
5. `scripts/e2e/old-saves.mjs` の期待する版を上げ、`browser.mjs` の `FAST_SETTINGS` の version も合わせる。
- 教材が変わって、セーブデータの「途中のイベントの段階の番号」がずれた場合は、範囲に収めて再開する（`resumeStep`）。壊れはしないが、前と違う場所から始まることがある（5章）。

### ブラウザでの確認（`scripts/e2e/`）
- 使い方は `scripts/e2e/README.md`。`npm run build` → `npm run preview` → `node scripts/e2e/first-day.mjs http://localhost:4173/seoul-life/`。公開URLでも同じように動かせる。
- ヘッドレスの Edge（なければ Chrome）を使う。追加のパッケージは不要。
- **ヘッドレスでは音が聞けず、韓国語の音声もない**（読み上げは「使えない」側の表示しか確かめられない）。音声認識の機能はあるが声は聞けないので、聞き取りの流れは偽の音声認識（`phase2.mjs`）で確かめる。実際の音・認識のよさは報告で「未確認」に入れる。
- 効果音は、ブラウザを「操作の前は音を出さない」設定で起動し、`Input.dispatchTouchEvent` の指のタップで確かめる。ただしヘッドレスの Edge は指が触れた瞬間も操作と認めるので、BUG-002 のような不具合は再現できない（実機で確かめる）。
- 重ねて出す板は `main` の外（`#overlay-root`）にあるので、`mainText()` では読めない。
- 教材を変えたら `first-day.mjs` の「教材に合わせた部分」を直す。`phase2.mjs` は小テストの正解を教材から求める。
- 開発サーバー（`npm run dev`）は起動直後に依存の準備で読み込み直すことがあり、1回目の確認が落ちることがある。流し直せば通る。
- 終わったらヘッドレスのブラウザが残っていないか確かめる（スクリプトは終了時に閉じるが、強制終了すると残ることがある）。

### 公開までの流れ（毎回）
1. `npm run typecheck` / `npm run lint` / `npm run test` / `npm run build` がすべて通る
2. `npm run preview` で `scripts/e2e/` を流す
3. コミット → `git push origin main`
4. GitHub API で Actions の完了（conclusion: success）を確かめ、公開URLでも `scripts/e2e/` を流す

## 4. 先送りにした課題

| 課題 | 今の動き | いつ決めるか |
|---|---|---|
| 「答えを見る」で進んだときの経験値 | 書く問題で2回間違えて「答えを見る」で進むと、その往復の経験値は付かない。正解の記録も付かないので、1日の終わりの「会話で正解」にも数えない | Phase 2.5（復習の仕組みと一緒に決める） |
| 音の変化のレッスンの小テスト | 「発音どおりの形を選ぶ」1種類だけになる | Phase 2.5（遊んだ感想を見て、必要なら調整） |
| レッスン12「1日目の言葉を読む」の組み立てる問題 | 3音節以下の単語が2語だけなので、組み立てる問題が少ない | Phase 2.5（同上） |
| 最初の案内の画面での「戻る」 | ブラウザの「戻る」でサイトを離れる | 必要になったら提案する |
| 途中まで進めたセーブデータの扱い | 教材が差し替わると、途中のイベントは「同じ番号の段階」から再開する（範囲外なら最後の段階）。覚える段階を飛ばすことがある。セーブデータに教材の版を持たせれば、最初からやり直させることもできる（形式の変更になるので要確認） | 教材の差し替えがあるとき（Phase 3 以降）に、必要なら提案する |
| カフェの背景のコーヒーミルの模様 | 文字のように見える模様がある（Phase 1.5 の Q9：今はそのまま）。Antigravity の検証では「文字状の破綻なし」と判定 | 画像を作り直すときに一緒に直す |

ほかに覚えておくこと：
- 自宅の背景は主人公の部屋の絵。近所の住人が来る場面は、玄関の背景に切り替えて解決済み。
