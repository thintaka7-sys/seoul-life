# 教材JSONの書き方

「서울에서 살기」の教材（単語・文法・会話・コラム・ハングルのレッスン・リスニングの文・基礎ドリル・章末テスト・聞き分けの組）と、イベント（単語を覚える段階と会話の順番）を JSON ファイルで作るための説明です。
教材を作るチャットに、このファイルと docs/CONTENT_STYLE.md をそのまま渡して使えます。

- 韓国語の書き方・カタカナの読み・正解の決め方は **docs/CONTENT_STYLE.md**（表記ルール）に従ってください。
- 教材を作る流れと確認の手順は GAME_SPEC.md 11-4 を参照してください。
- この説明と見本は、プログラムの検証ルールと一致しているかを自動テストで確かめています（`src/data/contentFormatDoc.test.ts`）。

**GAME_SPEC v2.3（Phase 1.5）での変更点**
- 会話を数往復にできるようにしました。`lines`・`choices`・`freeAnswer` は、`turns`（往復の配列）の中に書きます（8章）。前の書き方のファイルはエラーになります。
- 台詞ごとに、話す人の表情（`expression`）を指定できます（8-3）。
- 選択肢を選んだときの相手の反応（`reply`）を書けます（8-4）。
- コラム（韓国生活の小ネタ）を追加しました（9章）。イベントでは `column` の段階で使います（11章）。
- 店員と近所の住人の名前が決まりました（10-4）。
- イベントの途中で背景を切り替える段階（`background`）を追加しました（10-5、10-7、11-1）。

**GAME_SPEC v2.4（Phase 2）での変更点**
- ハングルのレッスンを追加しました（14章）。問題はプログラムが教材から自動で作るので、問題を1問ずつ書く必要はありません。
- 「聞いて正しい文を選ぶ」問題のための、リスニングの文を追加しました（15章）。リスニングのほかの2つの形式（聞いて単語を選ぶ・会話を聞いて返事を選ぶ）は、今ある単語と会話から自動で作るので、教材はいりません。

**GAME_SPEC v2.5（Phase 2.5）での変更点**
- 会話の答える往復に、何を言えばよいか（`task`）を書き、**正解を1つ**にします。話が変わるだけの場面は「選択の往復」（`"kind": "decision"`）にします（8-1・8-4・8-7）。
  - 不正解の選択肢には、相手の反応（`reply`）が必須になりました。
  - 問題の往復で `task` がなければエラーになります（1日目の会話を作り直したので、前の形の読み込みはなくしました）。
- 単語の `category` を、図鑑のタブになる `genre`（ジャンル）に置き換えました（6章・10-2）。`category` を書くとエラーになります。
- 文法に、接続ルールの説明（`connectionJa`）と、穴埋め問題で隠す部分（例文の `blank`・`blankWrong`）を書けるようにしました（7章）。
- 基礎ドリル（16章）と章末テスト（17章）を追加しました。
- 単語・文法・会話の問題（選ぶ・聞く・並べ替え・穴埋め・書く）は、プログラムが今ある教材から作ります。問題を1問ずつ書く必要はありません。

**GAME_SPEC v2.6（Phase 2.6）での変更点**
- 聞き分け練習（GAME_SPEC 4-10）のための「聞き分けの組」を追加しました（18章・10-9）。似た音の単語2〜4個を1つの組にします。問題はプログラムが組から作るので、1問ずつ書く必要はありません。
- ほかの教材の形は変わっていません。

## 1. ファイルの置き場所

| 種類 | フォルダ | ファイル名の例 |
|---|---|---|
| 単語 | `src/data/vocabulary/` | `ch01.json`、`ch03_cafe.json` |
| 文法 | `src/data/grammar/` | `ch02.json` |
| 会話 | `src/data/scenarios/` | `ch03_cafe.json` |
| コラム | `src/data/columns/` | `ch03.json` |
| イベント | `src/data/events/` | `day1.json`、`ch04.json` |
| ハングルのレッスン | `src/data/hangul/` | `lessons.json`（全レッスンを1ファイルにしても、分けてもよい） |
| リスニングの文 | `src/data/listening/` | `ch01.json`、`ch03.json` |
| 基礎ドリル | `src/data/drills/` | `numbers.json`、`days.json`（テーマごとに分けても、1ファイルにまとめてもよい） |
| 章末テスト | `src/data/tests/` | `ch01.json` |
| 聞き分けの組 | `src/data/ear/` | `consonants.json`、`vowels.json`（テーマごとに分けても、1ファイルにまとめてもよい） |

- フォルダに `.json` ファイルを置くと、自動で読み込まれます。ファイル名は自由です。章ごとに分けるのがおすすめです（`ch01.json`、`ch02.json` …）。
- 1つのファイルには、1種類のデータの**配列**（`[ … ]`）を入れます。単語と文法を同じファイルに混ぜないでください。
- 教材を渡すときは、`content-inbox/phase番号/` に同じフォルダ分けで置いてもらえれば、開発側で `src/data/` に移します。

## 2. JSONを書くときの決まり

- 文字コードは UTF-8 にします。
- 文字列は `"ダブルクォート"` で囲みます。シングルクォートは使えません。
- 最後の項目の後ろにカンマを付けません。JSON にはコメントも書けません。メモは `notes` 項目に書いてください。
- `true` / `false` と数字は、引用符で囲みません（`"level": 1`。`"level": "1"` は誤り）。
- 表にない項目名を書くとエラーになります。綴りの間違い（例：`pronounciation`）を見つけるためです。
- ハングルは普通に入力した文字で書きます。字母（ㅋ ㅓ ㅍ ㅣ）を並べた形にはしません。プログラムはUnicode正規化（NFC）された文字かどうかを確かめます。
  - ただし、ハングルのレッスン（14章）の `jamo`・`sound`・`letters`・`confusableWith` には字母を1つずつ書きます。説明の文（`introJa`・`tipJa`・`explanationJa`）の中でも、字母を使ってかまいません。

## 3. ID の決まり

- **一度ゲームに入れたIDは、後から変えたり使い回したりしません。** セーブデータと学習記録がIDで教材を参照しているためです。不要になった教材は削除してよいですが、そのIDは二度と使いません。
- **会話を作り直すときも、新しいIDにします。** 学習記録は「会話ID＋何往復目か」で付けているため、同じIDのまま往復の数や順番を変えると、記録がずれます。誤字の修正や、訳・読みの直しは、同じIDのままでかまいません。
- 単語・文法・会話・コラム・ハングルのレッスン・読む練習の単語・リスニングの文・基礎ドリル・章末テスト・ドリルとテストの問題・聞き分けの組のIDは、種類を通して重複できません。別のファイルにあっても重複はエラーになります。
- 番号は3桁以上にします（`001`、`002` … `999`、`1000`）。
- **900番台（`vocab_901` など）は、プログラムの仮データ用に予約しています。** 本番の教材では使わないでください。

| 種類 | 形式 | 例 |
|---|---|---|
| 単語 | `vocab_番号` | `vocab_001` |
| 文法 | `grammar_番号` | `grammar_001` |
| 会話 | `英小文字の名前_番号`（施設ID＋番号を推奨） | `cafe_001`、`convenience_store_001` |
| コラム | `column_番号` | `column_001` |
| イベント | `event_番号` | `event_001` |
| ハングルのレッスン | `hangul_番号` | `hangul_001` |
| 読む練習の単語（レッスンの `words`） | `hword_番号` | `hword_001` |
| リスニングの文 | `listen_番号` | `listen_001` |
| 基礎ドリル | `drill_番号` | `drill_001` |
| 章末テスト | `test_番号` | `test_001` |
| ドリル・テストの問題（`items` の各要素） | `dq_番号`（ドリルとテストで通し番号） | `dq_001` |
| 聞き分けの組 | `ear_番号` | `ear_001` |

## 4. 読み（カタカナのフリガナ）の決まり

韓国語の文には、カタカナの読みを付けます。ゲームでは、韓国語の上に**区切り（空白）ごと**にフリガナとして表示します。

- **韓国語と同じ位置で、半角スペースを1つ入れて区切ります。** 区切りの数が韓国語と違うとエラーになります。
  - 例：`아메리카노 한 잔 주세요.` → `アメリカノ ハン ジャン ジュセヨ`（どちらも4つ）
  - 韓国語の句読点は、前の語といっしょに1つの区切りとして数えます（`안녕하세요.` で1つ）。
- 読みに使える文字は、**カタカナ（ー を含む）と半角スペースだけ**です。句読点・ひらがな・全角スペースは入れません。先頭と末尾に空白を入れず、空白を2つ続けません。
- カタカナの書き方（連音化・濃音の「ッ」など）は docs/CONTENT_STYLE.md の1章に従います。

| 読みの項目 | 付ける場所 |
|---|---|
| `pronunciation` | 単語の見出し語、文法の例文、会話の台詞・選択肢・反応（`reply`）、コラムの韓国語、ハングルのレッスンの音節・単語・音の変化の例、リスニングの文、ドリル・テストの問題、聞き分けの組の音（`items`） |
| `examplePronunciation` | 単語の例文 |

書く問題の正解（`freeAnswer.answers`）と別解（`alternatives`）は、プレイヤーが書く答えなので読みを付けません。

## 5. 共通の項目

すべての単語・文法・会話・コラム・ハングルのレッスン・リスニングの文・基礎ドリル・章末テスト・聞き分けの組に付けます（レッスンの中の `words` と、ドリル・テスト・聞き分けの組の中の `items` には `reviewed` を付けず、まとめて示します）。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | 一意のID（3章） |
| `reviewed` | 必須 | true / false | 韓国語を確認済みか。作ったときは `false` にし、別のAIや韓国語母語話者の確認が済んだら `true` にする |
| `notes` | 任意 | 文字列 | 確認者のメモ（確認した人・日付・気になった点など） |

## 6. 単語

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 韓国語（見出し語）。正解判定では、これが模範解答になる |
| `alternatives` | 任意 | 文字列の配列 | 正解として認める別表記（例：`짜장면` に対する `자장면`）。1個以上入れる。`korean` と同じものは入れない |
| `pronunciation` | 必須 | 文字列 | 見出し語の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `partOfSpeech` | 必須 | キー | 品詞（10-1のキー一覧から選ぶ） |
| `genre` | 必須 | キー | ジャンル（10-2のキー一覧から選ぶ）。図鑑のタブになる |
| `level` | 必須 | 整数（1以上） | 難しさ。1がいちばんやさしい |
| `example` | 任意 | 文字列 | 例文（韓国語） |
| `examplePronunciation` | 任意 | 文字列 | 例文の読み（4章） |
| `exampleJapanese` | 任意 | 文字列 | 例文の日本語訳 |

- 例文の3項目（`example`・`examplePronunciation`・`exampleJapanese`）は、**3つそろえて書くか、3つとも省きます。**
- 空白の違い（分かち書き）と、句読点（. , ? !）、全角・半角の違いは、判定のときにプログラムが吸収します。そのため、こうした違いだけの別表記を `alternatives` に入れる必要はありません。
- 意味は同じでも別の単語（類義語）は、原則として `alternatives` に入れません。入れる場合は、`notes` に理由を書いてください。
- 単語の問題（韓国語→日本語・日本語→韓国語・聞いて選ぶ・文字の並べ替え・例文の穴埋め・日本語を見て書く）は、プログラムが作ります。例文の穴埋めは、`example` の中に `korean` がそのままの形で入っているときだけ出します。

## 7. 文法

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `title` | 必須 | 文字列 | 文法の名前（例：`이에요 / 예요`） |
| `level` | 必須 | 整数（1以上） | 難しさ |
| `explanation` | 必須 | 文字列 | 日本語での説明。初心者に分かる簡単な言葉で書く |
| `connectionJa` | 任意 | 文字列 | 接続ルールの説明（日本語。例：「名詞の最後にパッチムがあれば 이에요、なければ 예요」）。説明のためにハングルを入れてよい。文法カードに表示する |
| `examples` | 必須 | 配列（1個以上） | 例文。各要素は下の表のとおり |

`examples` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 例文（韓国語） |
| `pronunciation` | 必須 | 文字列 | 例文の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `alternatives` | 任意 | 文字列の配列 | 例文を答えさせる問題で、正解として認める別の言い方 |
| `blank` | 任意 | 文字列 | 穴埋め問題で隠す部分（例：`이에요`）。`korean` の中に**そのままの形で1回だけ**出てくる部分にする。文全体は不可 |
| `blankWrong` | `blank` があれば必須 | 文字列の配列（1個以上） | 穴埋め問題のまぎらわしい選択肢（例：`예요`）。`blank` と同じものは入れない |

文法の問題は、プログラムが例文から作ります。
- **穴埋め**：`blank` のある例文だけで出します。`blank` を空欄にし、`blank` と `blankWrong` から選びます。接続ルール（이에요 と 예요 など）の練習になるよう、`blankWrong` には間違えやすい形を入れます。
- **並べ替え**：例文を空白で区切った語を並べ替えます（区切りが2つ以上ある例文だけ）。教材に書き足すものはありません。
- **日本語を見て書く**：`japanese` を見て例文を書きます。`korean` と `alternatives` を正解にします。

## 8. 会話

1つの会話は、1つ以上の**往復**（`turns`）でできています。1往復は「相手の台詞 → プレイヤーの返事 → 相手の反応」です。

```
往復1：台詞（lines）→ 返事（choices / freeAnswer）→ 反応（reply）
往復2：台詞（lines）→ 返事 → 反応
…
最後の往復：締めの台詞（lines）だけでもよい
```

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `chapter` | 必須 | 整数（1〜10） | 何章の会話か（GAME_SPEC 5章） |
| `location` | 必須 | キー | 会話する施設（10-3） |
| `character` | 必須 | キー | 会話の相手（10-4。`player` は使えない）。この人の立ち絵を表示する |
| `turns` | 必須 | 配列（1個以上） | 往復を順番に並べる（8-1） |

### 8-1. 往復（`turns` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `kind` | 任意 | `"decision"` | 選択の往復にするときだけ `"decision"` と書く（8-7）。問題の往復では書かない |
| `task` | 問題の往復では必須 | 文字列 | 何を言えばよいか（日本語。例：「コーヒーを注文しよう」）。選ぶ・書く・話すのどの画面でも「言うこと」として表示する。ハングルは入れない。選択の往復では任意 |
| `lines` | 下を参照 | 配列 | プレイヤーが答える前の台詞（8-2）。画面では1つずつ表示する |
| `choices` | 任意 | 配列 | 選んで答えるときの選択肢（8-4）。問題の往復では1個以上で、`"correct": true` を**ちょうど1つ**。選択の往復では2個以上 |
| `freeAnswer` | 任意 | オブジェクト | 書いて（話して）答えるときのお題と正解（8-5）。問題の往復にだけ書ける |

- **`choices` のある往復**が、プレイヤーが答える往復です。会話には1つ以上必要です。
- **`choices` のない往復**は、台詞だけの往復です。**会話の最後の往復（締めの台詞）にだけ**使えます。`lines` を1つ以上入れます。`kind`・`task` は書けません。
- `lines` は、**最初の往復では必須**（1つ以上）です。2つ目以降の、`choices` のある往復では省略できます（前の往復の反応 `reply` が、そのまま次の質問になっている場合など）。
- 経験値と学習記録は、問題の往復ごとに付きます（選んで正解・書いて正解、それぞれ初めてのときだけ）。正解した問題の往復は、復習にも入ります。選択の往復には付きません。

### 8-2. 台詞（`lines` と `reply` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `speaker` | 必須 | キー | 話す人（10-4） |
| `korean` | 必須 | 文字列 | 台詞（韓国語） |
| `pronunciation` | 必須 | 文字列 | 台詞の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `expression` | 任意 | キー | 話すときの表情（10-6）。主人公（`player`）の台詞には付けられない |

### 8-3. 表情（`expression`）

会話の相手（`character`）の立ち絵は、台詞に合わせて表情が変わります。

- 台詞に `expression` を書くと、**いつもその表情**になります。
- 書かなかったときは、プログラムが自動で決めます。

| 場面 | 自動で決まる表情 |
|---|---|
| ふだんの台詞（`lines`） | `normal`（通常） |
| プレイヤーが正解した直後と、その反応（`reply`） | `smile`（笑顔） |
| プレイヤーが間違えた直後と、間違えた選択肢の反応（`reply`） | `troubled`（困り顔） |
| 「答えを見る」で進んだ直後と、その反応 | `normal` |

- 相手以外（主人公など）が話している間は、直前の相手の表情のままです。
- 自動の表情と違う顔にしたいときだけ、`expression` を書けば十分です（例：正解の反応でも、驚いた・困った返事なら `"expression": "troubled"`）。

### 8-4. 選択肢（`choices` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 選択肢（韓国語）。同じ往復の中で重複させない |
| `pronunciation` | 必須 | 文字列 | 選択肢の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳。間違えたときに「〜という意味です」と表示するのにも使う |
| `correct` | 問題の往復では必須 | true / false | 正解か。問題の往復では、`true` をちょうど1つにする。選択の往復では書かない |
| `reply` | 下を参照 | 配列（1個以上） | この選択肢を選んだときの相手の反応（台詞。8-2）。1つずつ表示する |

- **正解の選択肢の `reply`**（任意）：主人公の返事の後に表示し、次の往復へ進みます。書かなかった場合は、すぐ次の往復へ進みます。
- **不正解の選択肢の `reply`**（必須）：「〜という意味です。もう一度選んでみましょう」の案内と一緒に表示し、プレイヤーはもう一度選びます（例：店を出るあいさつを選ぶと、店員が「네?」と聞き返す）。困った顔・聞き返すなど、相手が反応するようにします（GAME_SPEC 4-4）。
- **選択の往復の `reply`**（必須）：選んだものに合わせた反応です。表示した後、次の往復へ進みます。
- 不正解の選択肢は、初心者が間違えやすいものにします（場面に合わないあいさつ、似た音の言葉など。CONTENT_STYLE 3章）。

### 8-5. 書いて答える（`freeAnswer`）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `prompt` | 必須 | 文字列 | 日本語のお題（例：「コーヒーをください」） |
| `answers` | 必須 | 文字列の配列（1個以上） | 正解。**先頭が模範解答**で、2つ目以降が別解。自然な言い方が複数ある場合は、すべて入れる |
| `reply` | 任意 | 配列（1個以上） | 書いて正解したときの相手の反応（8-2） |

- `prompt` は `task` と同じ内容にします（`task` が「何を言うか」、`prompt` が「どう言うか」の日本語。例：`task`「コーヒーを注文しよう」、`prompt`「コーヒーをください」）。
- 書いて正解したときの反応は、次の順で決まります：`freeAnswer.reply` → 書いた答えと同じ文の選択肢の `reply` → 正解の選択肢の `reply`。

### 8-6. 書くときの目安

- 丁寧語とタメ口の使い分けは docs/CONTENT_STYLE.md の2章に従います。
- 1つの会話の中の往復は、同じ場面のひと続きのやりとりにします。場面が変わるとき（店に入る → 席に着く など）は、別の会話にしてイベント（11章）で並べます。

### 8-7. 問題の往復と選択の往復（GAME_SPEC 4-4）

| | 問題の往復（`kind` を書かない） | 選択の往復（`"kind": "decision"`） |
|---|---|---|
| 使う場面 | 言うべきことが決まっている（あいさつする、お礼を言う、注文する） | 選んだ内容で話が変わるだけ（ケーキも頼むか、はい・いいえのどちらで答えてもよい質問） |
| `task` | 必須（例：「お礼を言おう」） | 任意（例：「ケーキも頼むか決めよう」） |
| 選択肢 | 正解（`"correct": true`）がちょうど1つ。不正解には `reply` が必須 | `correct` を書かない。2個以上で、すべてに `reply` が必須 |
| 書く・話す（`freeAnswer`） | 書ける | 書けない（選ぶだけ） |
| 経験値・学習記録・復習 | あり | なし（「声に出して言ってみる」の練習はできる） |

- 選択の往復は、相手の反応（`reply`）だけが変わります。その後の往復は、どれを選んでも同じです。
- 好きなものを自由に注文する場面は、Phase 3 の「注文」（書く・話す専用）で作ります。今は選択の往復にします。

## 9. コラム（韓国生活の小ネタ）

イベントの途中で、韓国での暮らしに役立つ小ネタを読む画面です。経験値は付きません。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `chapter` | 必須 | 整数（1〜10） | 何章のコラムか（フリガナをいつも出すかどうかの判定に使う） |
| `titleJa` | 必須 | 文字列 | 見出し（日本語。ハングルは入れない） |
| `blocks` | 必須 | 配列（1個以上） | 本文。上から順に表示する。各要素は下の表のどちらか |

`blocks` の各要素：

| `type` | ほかの項目 | 意味 |
|---|---|---|
| `text` | `textJa`（必須） | 日本語の文。**ハングルは入れない** |
| `korean` | `korean`・`pronunciation`・`japanese`（すべて必須） | 韓国語の語句や文。フリガナと読み上げボタンを付けて表示する。読みは4章の決まりに従う |

## 11. イベント

イベントは「どの施設で、何を、どの順に行うか」を決めるデータです。教材とあわせて下書きしてください。プレイヤーは、前提のイベントを終えた後に、その施設で「`actionJa`」のボタンを押してイベントを始めます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `event_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章のイベントか。フリガナをいつも出すかどうかの判定にも使う |
| `location` | 必須 | キー | イベントが起きる施設（10-3） |
| `requires` | 必須 | 文字列の配列 | 先に終えておくイベントのID。最初のイベントは `[]` |
| `objectiveJa` | 必須 | 文字列 | 目標として画面の上に出す文（例：「カフェで注文してみよう」） |
| `actionJa` | 必須 | 文字列 | 施設の画面に出す、イベントを始めるボタンの文字（例：「カウンターへ行く」） |
| `steps` | 必須 | 配列（1個以上） | 段階を順番に並べる（10-5） |
| `notes` | 任意 | 文字列 | メモ |

**決まり**
- **日本語の文（`objectiveJa`・`actionJa`・`textJa`）には、ハングルを入れません。** 韓国語を見せたいときは、単語・文法・会話・コラムの教材として作り、`learn`・`conversation`・`column` で使います。
- `conversation` で使う会話は、イベントと同じ施設の会話にします。1つの会話は、1つのイベントでしか使えません。
- 単語は、その単語が初めて出てくる会話より前の `learn` で覚えるようにします。1度に覚える単語は、5〜7語くらいまでを目安にします。
- `requires` に書いたイベントが存在しない場合や、前提が循環している場合はエラーになります。
- 同じ施設で始められるイベントが複数あるときは、ファイルの中で先に書いたものから始まります。

### 11-1. 背景を切り替える（`background`）

イベントの途中で、背景を施設のふだんの背景から別の絵に切り替えられます（例：自宅のイベントで、玄関に出てお隣さんと話す場面）。

```json
"steps": [
  { "type": "message", "textJa": "玄関のチャイムが鳴りました。" },
  { "type": "background", "id": "entrance" },
  { "type": "learn", "vocabulary": ["vocab_001"] },
  { "type": "conversation", "id": "home_003" },
  { "type": "background", "id": "home" },
  { "type": "column", "id": "column_001" }
]
```

- 切り替えた背景は、次の `background` の段階か、イベントの終わりまで続きます。間にある `learn`・`message`・`column` なども、その背景のまま表示します（会話ごとに部屋と玄関を行き来しないようにするため）。
- 元の背景に戻すときは、施設ID（上の例では `home`）を書きます。
- `background` の段階は画面に何も出さず、すぐ次の段階に進みます。イベントの最後の段階には置けません（イベントが終わると、施設のふだんの背景に戻るため）。
- 背景の画像がまだない場合は、施設のふだんの背景のまま進みます。

## 14. ハングルのレッスン（GAME_SPEC 4-1）

ハングルを読めない人のための導入です。プレイヤーは自宅の「勉強する」→「ハングル」でレッスンを選びます。どのレッスンも最初から選べ、おすすめの順番（`order`）で並びます。

レッスンの中の問題は、プログラムが教材から**自動で作ります**。教材側で問題を1問ずつ書く必要はありません。

1. 文字を見る・聞く（`introJa`、文字ごとの `tipJa` と聞かせる音節 `sounds`）
2. 聞いて文字を選ぶ／文字を見て読み（カタカナ）を選ぶ
3. ゲーム内キーボードで音節を組み立てる
4. 単語を読む（`words`・`vocabulary`）
5. 小テスト（合格すると完了の印が付く）

- 読む練習の単語（`words`）は、図鑑には入りません（レッスンの中だけで使います）。
- 端末に韓国語の音声がないときは、「聞いて選ぶ」問題を、聞かせる音節のカタカナを見て選ぶ問題に置き換えます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `order` | 必須 | 整数（1以上） | 並び順。ほかのレッスンと重複できない。**習った文字の範囲**（14-6）もこの順で決まる |
| `kind` | 必須 | キー | レッスンの種類（10-8） |
| `titleJa` | 必須 | 文字列 | レッスンの名前（日本語。**ハングルは入れない**。一覧に表示する） |
| `introJa` | 必須 | 文字列の配列（1個以上） | 導入の説明。1要素が1段落。字母やハングルを入れてよい |
| `letters` | 下を参照 | 配列（1個以上） | 覚える文字（14-1）。`kind` が `letters` のときだけ書く |
| `finals` | 下を参照 | 配列（1個以上） | パッチムのグループ（14-3）。`kind` が `batchim` のときだけ書く |
| `rules` | 下を参照 | 配列（1個以上） | 音の変化のルール（14-4）。`kind` が `soundChange` のときだけ書く |
| `words` | 下を参照 | 配列（1個以上） | 読む練習の単語（14-5） |
| `vocabulary` | 下を参照 | 文字列の配列 | 読む練習に使う、教材の単語のID（`vocab_001` など）。`kind` が `reading` のときだけ書ける。見出し語（`korean`）を読む |

どの項目を書くかは `kind` で決まります（10-8 の表）。表にない項目を書くとエラーになります。

### 14-1. 文字（`letters` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `jamo` | 必須 | 字母1つ | 覚える字母（例：`ㄱ`、`ㅏ`）。子音19個・母音21個のどれか。**ほかのレッスンと重複できない** |
| `sounds` | 必須 | 配列（1個以上） | 聞かせる音節（14-2） |
| `tipJa` | 必須 | 文字列 | 発音のこつ（日本語）。日本語の音との違い、口の形など |
| `confusableWith` | 任意 | 字母の配列 | まぎらわしい字母（例：`ㅓ` に対する `ㅗ`）。「聞いて選ぶ」問題で選択肢に混ぜる。自分自身は入れない |

### 14-2. 聞かせる音節（`sounds` の各要素）

字母（ㄱ など）をそのまま読み上げると、「기역」のように**字母の名前**で読まれてしまいます。そのため、音は**音節**で聞かせます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 1音節 | 読み上げる音節（例：`가`） |
| `pronunciation` | 必須 | 文字列 | その音節の読み（カタカナ。空白なし） |

- **母音**：文頭に ㅇ を付けた音節にします（ㅏ → `아`）。パッチムは付けません。
- **子音**：その子音で始まる音節を2〜3個にします（ㄱ → `가`・`고`・`구`）。いろいろな母音と組み合わせると、子音の音を聞き分けやすくなります。パッチムは付けません。
- **パッチム**（14-3）：パッチムのある音節にします（ㄱ のグループ → `악`）。
- 1つ目の音節が、その文字のいちばん大事な音です（一覧や小テストで最初に使います）。
- 読み（カタカナ）は、端末に韓国語の音声がないときの置き換え問題にも使います。

### 14-3. パッチムのグループ（`finals` の各要素）

パッチムは、発音が7つの代表音（ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅇ）のどれかになります。代表音ごとに1つのグループにします。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `sound` | 必須 | 字母1つ | 代表音（`ㄱ` `ㄴ` `ㄷ` `ㄹ` `ㅁ` `ㅂ` `ㅇ` のどれか） |
| `letters` | 必須 | 字母の配列（1個以上） | この音になるパッチムの字母（例：ㄱ のグループなら `ㄱ` `ㅋ` `ㄲ`）。二重パッチム（`ㅄ` など）も入れられる。**同じ字母を2つのグループに入れない** |
| `sounds` | 必須 | 配列（1個以上） | 聞かせる音節（14-2）。パッチムが `letters` のどれかの音節 |
| `tipJa` | 必須 | 文字列 | 発音のこつ |

- **パッチムは、ここで `letters` に入れた字母だけが「習った」ことになります**（14-6）。後のレッスンで使う言葉のパッチム（二重パッチムを含む）は、どれかのグループに入れておいてください。
- 二重パッチムは、概要を `introJa` で説明し、よく出るもの（없어요 の `ㅄ` など）を、読む音のグループの `letters` に入れます。

### 14-4. 音の変化のルール（`rules` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `titleJa` | 必須 | 文字列 | ルールの名前（例：「連音化」。ハングルは入れない） |
| `explanationJa` | 必須 | 文字列 | 説明（日本語。字母やハングルを入れてよい） |
| `examples` | 必須 | 配列（1個以上） | 例（下の表）。3〜4個が目安 |

`examples` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 書いた形（例：`음악`）。これを読み上げる |
| `spoken` | 必須 | 文字列 | 発音どおりにハングルで書いた形（例：`으막`）。`[으막]` のように表示する。`korean` と同じ位置で空白を入れる |
| `pronunciation` | 必須 | 文字列 | 読み（4章。発音どおりのカタカナ） |
| `japanese` | 必須 | 文字列 | 意味 |

- 読み上げは、書いた形（`korean`）をそのまま読ませます。ふつうは、音の変化をした正しい発音で読まれます。

### 14-5. 読む練習の単語（`words` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `hword_番号`（3章）。ほかの教材のIDと重複できない |
| `korean` | 必須 | 文字列 | 韓国語 |
| `pronunciation` | 必須 | 文字列 | 読み（4章） |
| `japanese` | 必須 | 文字列 | 意味 |

- 1レッスンに**4〜8語**が目安です。プログラムは1語以上あればよいとしています（母音だけのレッスンでは、書ける単語が少ないため）。
- 同じレッスンの中で、同じ韓国語を2回入れないでください。

### 14-6. 習った文字の範囲（プログラムが確かめること）

レッスンの中の韓国語（聞かせる音節・`words`・音の変化の例・`vocabulary` の単語）は、**そのレッスンまでに習った文字だけ**で書けていなければなりません。書けていないとエラーになり、そのレッスンは読み込まれません。

- 「そのレッスンまで」とは、`order` がそのレッスン以下のレッスンのことです（そのレッスン自身を含む）。
- **文字**：`letters` のレッスンの `jamo` で習ったものが使えます。複合母音（ㅘ など）は、その複合母音として習ったものだけが使えます（ㅗ と ㅏ を習っただけでは使えない）。
- **文頭の ㅇ**：音がない文字なので、どのレッスンでも使えます（母音のレッスンで `아이` などを書けるようにするため）。
- **パッチム**：`batchim` のレッスンの `finals` の `letters` に入れたものだけが使えます。**パッチムのレッスンより前のレッスンでは、パッチムのある言葉はエラーになります**（例：子音のレッスンで `수박` は使えない）。パッチムの ㅇ（`방` など）も同じです。

### 14-7. レッスンの分け方（Phase 2 の予定）

全部で12本です。1度に覚える文字は5〜7個までを目安にしています。

| `order` | `kind` | レッスン | 覚えるもの |
|---|---|---|---|
| 1 | `letters` | 基本の母音（1） | ㅏ ㅓ ㅗ ㅜ ㅡ ㅣ |
| 2 | `letters` | 基本の母音（2） | ㅑ ㅕ ㅛ ㅠ |
| 3 | `letters` | 基本の子音（1） | ㄱ ㄴ ㄷ ㄹ ㅁ（有声音化の説明を含む） |
| 4 | `letters` | 基本の子音（2） | ㅂ ㅅ ㅇ ㅈ ㅎ（有声音化の説明を含む） |
| 5 | `letters` | 激音 | ㅊ ㅋ ㅌ ㅍ |
| 6 | `letters` | 濃音 | ㄲ ㄸ ㅃ ㅆ ㅉ |
| 7 | `letters` | 複合母音（1） | ㅐ ㅔ ㅒ ㅖ ㅘ ㅝ |
| 8 | `letters` | 複合母音（2） | ㅙ ㅞ ㅚ ㅟ ㅢ |
| 9 | `batchim` | パッチム | 7つの代表音のグループ。二重パッチムの概要と、よく出るもの3〜4個 |
| 10 | `soundChange` | 音の変化（1） | 連音化・ㅎの弱化・激音化 |
| 11 | `soundChange` | 音の変化（2） | 鼻音化・濃音化・口蓋音化 |
| 12 | `reading` | 第1章の言葉を読む | 教材の単語（`vocabulary`）を読む |

- 有声音化（語中で「カ」が「ガ」のように濁る）は、子音のレッスン（3・4）の `introJa` か `tipJa` で説明します。
- 流音化は、Phase 3 以降で必要になったら足します。
- 第1章の言葉を読むレッスン（12）では、`vocabulary` に入れた単語の見出し語も、習った文字の範囲を確かめます。二重パッチムなどがあれば、9 の `finals` に入れておいてください。

**必要な数の目安**

| 種類 | 数 |
|---|---|
| レッスン | 12本（導入の説明は各2〜4段落） |
| 文字（`letters`） | 40字（母音21・子音19） |
| パッチムのグループ（`finals`） | 7グループ |
| 聞かせる音節（`sounds`） | 母音は各1個、子音は各2〜3個、パッチムは各グループ1〜2個 |
| 読む練習の単語（`words`） | 各レッスン4〜8語、合計50〜80語 |
| 音の変化の例 | 6ルール×3〜4例、合計18〜24例 |

### 14-8. 書くときの目安

- カタカナが同じになる字母（ㅓ と ㅗ、ㅐ と ㅔ など）は、`tipJa` で違いを説明し、`confusableWith` にお互いを入れます。プログラムは、カタカナを選ぶ問題では、同じカタカナの選択肢を一緒に出しません。
- `words` には、なるべく実際によく使う言葉を選びます。意味のない音の並びは避けます。
- レッスンの `reviewed` は、レッスン全体（説明・音節・単語・例）を確認してから `true` にします。

## 15. リスニングの文（GAME_SPEC 4-5）

学習画面の「リスニング」で出す「聞いて正しい文を選ぶ」問題です。正解の文を読み上げ、正解の文とまぎらわしい文の中から選ばせます。答えた後に、それぞれの文の意味を表示します。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `afterEvent` | 必須 | 文字列 | このイベント（`event_001` など）を終えたら出題する。フリガナの表示も、このイベントの章に合わせる |
| `korean` | 必須 | 文字列 | 正解の文（読み上げる文） |
| `pronunciation` | 必須 | 文字列 | 読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `distractors` | 必須 | 配列（1個以上） | まぎらわしい文。各要素は `korean`・`pronunciation`・`japanese`（すべて必須）。2つが目安 |

- まぎらわしい文は、**聞き間違えやすい文**にします（同じ単語で語尾が違う、似た音の単語に入れ替える など）。意味がまったく違う文だと、聞かなくても選べてしまいます。
- 正解の文と、空白（分かち書き）や句読点の違いだけの文は、聞いても区別できないので使えません（エラーになります）。
- 文に使う単語・文法は、`afterEvent` のイベントまでに覚えたものにします。
- Phase 2 では、1日目のイベント（`event_001` の自宅、`event_002` のカフェ）の内容から **8〜10問**が目安です。
- 「聞いて単語を選ぶ」と「会話を聞いて返事を選ぶ」の問題は、覚えた単語と終えた会話から自動で作るので、教材はいりません（返事を選ぶ問題は、問題の往復の正解の選択肢から作ります。選択の往復は使いません）。

## 16. 基礎ドリル（GAME_SPEC 4-9）

数字・曜日・値段など、毎日の暮らしで必ず使う基礎を、物語と関係なく練習するためのテーマです。学習画面からいつでも選べます。
1つのドリルは1つのテーマで、問題（`items`）を並べたものです。**問題の形（選ぶ・聞く・書く）はプログラムが決める**ので、1問ごとに「韓国語と、その意味」を書きます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `drill_番号`（3章） |
| `titleJa` | 必須 | 文字列 | テーマの名前（日本語。例：「数字（漢数詞）」）。ハングルは入れない |
| `introJa` | 任意 | 文字列 | 始める前に見せる説明（日本語）。説明のためにハングルを入れてよい（例：「일・이・삼 … は値段や日付に使う数え方です」） |
| `questionCount` | 任意 | 整数（1〜50） | 1回の問題数。省略したら10問。問題（`items`）より多いときは、`items` の数だけ出す |
| `items` | 必須 | 配列（4個以上） | 問題。各要素は下の表のとおり |
| `reviewed`・`notes` | | | 5章 |

### 16-1. 問題（`items` の各要素。章末テストの `items` も同じ形）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `dq_番号`。ドリルとテストをまたいで一意にする（復習の記録がこのIDで参照するため） |
| `korean` | 必須 | 文字列 | 韓国語（模範解答） |
| `alternatives` | 任意 | 文字列の配列（1個以上） | 正解として認める別の言い方（例：`하나` に対する `한 개`）。`korean` と同じものは入れない。**韓国語（ハングル）で書く**（数字だけの別解は入れられない） |
| `pronunciation` | 必須 | 文字列 | `korean` の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語。数字の問題では、画面に出す数の書き方（例：`3,500ウォン`、`3時30分`）。ハングルは入れない |
| `digits` | 任意 | 文字列 | **数字の問題にするときだけ**書く。プレイヤーが入力する数字（半角。例：`3500`）。時刻・日付は `:` と `/` で区切る（例：`3:30`、`5/15`）。カンマや単位は入れない |
| `hintJa` | 任意 | 文字列 | 問題に添えるひとこと（日本語。例：「固有数詞で」）。ハングルは入れない |

### 16-2. 出題のしかた（プログラムが決めること）

- **数字の問題**（`digits` あり）：選択肢は出しません（選択肢がヒントになるため。GAME_SPEC 4-2）。
  - 韓国語を見て（または聞いて）、数字を入力する → `digits` と比べます。
  - 日本語（`japanese`）を見て、韓国語をゲーム内キーボードで入力する → `korean` と `alternatives` だけを正解にします。**数字（`3500` など）で書いた答えは正解にしません**（読み方を書く練習のため）。
- **数字でない問題**（`digits` なし）：韓国語→日本語を選ぶ、日本語→韓国語を選ぶ、聞いて選ぶ（音声があるときだけ）、日本語を見て韓国語を書く、を混ぜます。
  - 選択肢は、**同じドリルのほかの問題**から作ります。そのため、1つのドリルには同じ種類のもの（曜日なら曜日だけ）を入れます。
- 間違えた問題は復習（GAME_SPEC 7-5）に入り、間隔を空けてもう一度出ます。

### 16-3. 書くときの目安

- 1テーマ **10〜20問**。
- 漢数詞と固有数詞は、**テーマを分けます**（「数字（漢数詞）」「数字（固有数詞）」）。1つのドリルに混ぜるときは、`hintJa` で「漢数詞で」「固有数詞で」と示します。
- 値段・時刻は、数字と単位を組み合わせた形にします（例：`삼천오백 원`、`세 시 삼십 분`）。読み（`pronunciation`）は CONTENT_STYLE 1章のとおり、実際の発音どおりに書きます。数と単位の間（空白をまたぐところ）の連音化も反映します（例：`삼천오백 원` → サムチョノベ グォン、`오백 원` → オベ グォン）。
- 固有数詞の数え方（`하나` と `한 개` など）、分かち書きのゆれ以外の別の言い方は、`alternatives` に入れます。空白の違いだけの別解は入れる必要はありません（プログラムが吸収します）。

## 17. 章末テスト（GAME_SPEC 4-9）

章の終わりに、その章の内容を確かめるテストです。**問題はプログラムが、その章の単語・文法・会話から自動で作ります。** 教材として書くのは、テストの名前・問題数・合格の基準と、足したい問題（任意）だけです。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `test_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章のテストか。**1つの章にテストは1つまで** |
| `titleJa` | 必須 | 文字列 | テストの名前（日本語。例：「第1章のテスト」）。ハングルは入れない |
| `questionCount` | 任意 | 整数（1〜50） | 問題数。省略したら10問 |
| `passPercent` | 任意 | 整数（0〜100） | 合格の基準（正解の割合）。省略したら80 |
| `items` | 任意 | 配列（1個以上） | 自動で作る問題に混ぜる問題。形は基礎ドリルの問題（16-1）と同じ |
| `reviewed`・`notes` | | | 5章 |

- 自動で作る問題のもと：
  - その章のイベント（`chapter` が同じ）の単語カード・文法カードで覚える単語・文法
  - その章の会話（`chapter` が同じ）の問題の往復。「言うこと」（`task`）を見て返事を選ぶ・書く
- テストは、**その章の会話の問題の往復に、すべて一度は答えたら**受けられます。
- 間違えた問題は復習に入ります。初めて合格したときに経験値が付きます。

## 18. 聞き分けの組（GAME_SPEC 4-10）

日本語話者が聞き分けにくい、似た音を聞く練習のための組です。組の中の1つを読み上げ、どれだったかを**同じ組の中から**選ばせます。どの組を作るかは、docs/STUMBLING_POINTS.md（つまずきリスト）の「聞き分け練習の最初の組」をもとに決めます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `ear_番号`（3章） |
| `theme` | 必須 | 文字列 | テーマ（10-9） |
| `titleJa` | 必須 | 文字列 | 組の名前（例：「ㅂ・ㅍ・ㅃ」）。聞き分ける字母を入れてよい |
| `focusJa` | 必須 | 文字列 | どこを聞き分けるか（例：「最初の子音の息の出方」）。組の一覧に出す |
| `tipJa` | 必須 | 文字列 | 聞き分けのこつ（1〜2文）。答えた後に出す。字母や単語を入れてよい |
| `stumbling` | 任意 | 文字列の配列（1個以上） | つまずきリストのID（例：`["S01"]`） |
| `items` | 必須 | 配列（2〜4個） | 組の音。各要素は下の表のとおり |
| `reviewed`・`notes` | | | 5章 |

### 18-1. 組の音（`items` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 読み上げる単語（ハングル） |
| `pronunciation` | 必須 | 文字列 | 読み（4章）。組の中で同じカタカナになってもかまいません（불・풀 はどちらも「プル」） |
| `japanese` | 必須 | 文字列 | 意味。**1つに絞ります**（밤 は「夜」か「栗」のどちらか）。組の中で同じ意味は使えません。ハングルは入れない |

- 組の中で、同じ韓国語（空白・句読点の違いだけのものを含む）は使えません（エラーになります）。

### 18-2. 出題のしかた（プログラムが決めること）

- 組の中から1つを読み上げ、組の音をすべて選択肢にします（ほかの組の音は混ぜません）。読み上げる音は、組の中でほぼ同じ回数になるようにします。
- 選択肢には、答える前から韓国語と意味を出します。フリガナは、答えるまで出しません（同じカタカナになることが多く、まぎらわしいため）。
- 答えた後に、選んだ音と正解の音を聞き比べられるようにし、`tipJa` を出します。
- 間違えた組は、復習（GAME_SPEC 7-5）に入ります。

### 18-3. 書くときの目安

- **実在する短い単語**にします（1音節だけの読み上げは、端末ではっきりしないことがあるため）。
- 聞き分けるところ（`focusJa`）以外は、できるだけ同じ音にします（불・풀・뿔 は最初の子音だけが違う）。
- 同じ音で意味の違う言葉（눈＝目・雪 など）は、聞いても区別できないので、同じ組に入れません。
- 実機で聞き分けにくい組は使いません。ゲームの「試しに聞く」で、組ごとに確かめられます。
