# 教材JSONの書き方

「서울에서 살기」の教材（単語・文法・会話・コラム・ハングルのレッスン・リスニングの文・基礎ドリル・章末テスト・聞き分けの組・おはなし・読み物・メニュー・注文）と、イベント（単語を覚える段階と会話の順番）を JSON ファイルで作るための説明です。
教材を作るチャットに、このファイルと docs/CONTENT_STYLE.md をそのまま渡して使えます。

- 韓国語の書き方・カタカナの読み・正解の決め方は **docs/CONTENT_STYLE.md**（表記ルール）に従ってください。
- 教材を作る流れと確認の手順は GAME_SPEC.md 11-4 を参照してください。
- この説明と見本は、プログラムの検証ルールと一致しているかを自動テストで確かめています（`src/data/contentFormatDoc.test.ts`）。

**GAME_SPEC v2.3（Phase 1.5）での変更点**
- 会話を数往復にできるようにしました。`lines`・`choices`・`freeAnswer` は、`turns`（往復の配列）の中に書きます（8章）。前の書き方のファイルはエラーになります。
- 台詞ごとに、話す人の表情（`expression`）を指定できます（8-3）。
- 選択肢を選んだときの相手の反応（`reply`）を書けます（8-4）。
- コラム（韓国生活の小ネタ）を追加しました（9章）。イベントでは `column` の段階で使います（11章）。
- 店員と近所の住人の名前が決まりました（10-4）。
- イベントの途中で背景を切り替える段階（`background`）を追加しました（10-5、10-7、11-1）。

**GAME_SPEC v2.4（Phase 2）での変更点**
- ハングルのレッスンを追加しました（14章）。問題はプログラムが教材から自動で作るので、問題を1問ずつ書く必要はありません。
- 「聞いて正しい文を選ぶ」問題のための、リスニングの文を追加しました（15章）。リスニングのほかの2つの形式（聞いて単語を選ぶ・会話を聞いて返事を選ぶ）は、今ある単語と会話から自動で作るので、教材はいりません。

**GAME_SPEC v2.5（Phase 2.5）での変更点**
- 会話の答える往復に、何を言えばよいか（`task`）を書き、**正解を1つ**にします。話が変わるだけの場面は「選択の往復」（`"kind": "decision"`）にします（8-1・8-4・8-7）。
  - 不正解の選択肢には、相手の反応（`reply`）が必須になりました。
  - 問題の往復で `task` がなければエラーになります（1日目の会話を作り直したので、前の形の読み込みはなくしました）。
- 単語の `category` を、図鑑のタブになる `genre`（ジャンル）に置き換えました（6章・10-2）。`category` を書くとエラーになります。
- 文法に、接続ルールの説明（`connectionJa`）と、穴埋め問題で隠す部分（例文の `blank`・`blankWrong`）を書けるようにしました（7章）。
- 基礎ドリル（16章）と章末テスト（17章）を追加しました。
- 単語・文法・会話の問題（選ぶ・聞く・並べ替え・穴埋め・書く）は、プログラムが今ある教材から作ります。問題を1問ずつ書く必要はありません。

**GAME_SPEC v2.6（Phase 2.6）での変更点**

- ほかの教材の形は変わっていません。

**GAME_SPEC v2.7（Phase 3）での変更点**
- 物語を章立てにしました。章の一覧、イベントの `start`（自動で始まる）・`unlocks`（施設が開く）、新しい段階（`story`・`reading`・`order`・`listening`・`chapterEnd`・`hangulIntro`）を足しました（19章）。第1〜3章のイベントのIDと組み立ての案は 19-4 にあります。
- おはなし（20章）、読み物（25章）、メニュー（26章）、注文（27章）を追加しました。
- 台詞・本文の単語をタップして意味を見るための `glosses` を、会話の台詞にも書けるようにしました（21章・8-2）。
- 学習画面の説明は、先生が話す形で出します。教材の形は変わりません（22章）。
- ハングルのレッスン・文法・基礎ドリル・聞き分けの組に、図や絵（`figures`）を付けられるようにしました（23章）。
- 単語に、元の形（`base`）と形が変わった言葉（`forms`）を書けるようにしました（24章・10-12）。
- キャラクターに、先生（`teacher`）と、立ち絵のない人物（`taxi_driver`・`airport_staff`・`announcement`）を足しました。友人と先生の名前は確認済みです（10-4。ChatGPT、2026-11-23）。
- 場面の背景に `airport`・`taxi`・`street` を足しました（10-7）。
- 今までの教材は、そのまま読み込めます（書き直しは不要です）。

## 2. JSONを書くときの決まり

- 文字コードは UTF-8 にします。
- 文字列は `"ダブルクォート"` で囲みます。シングルクォートは使えません。
- 最後の項目の後ろにカンマを付けません。JSON にはコメントも書けません。メモは `notes` 項目に書いてください。
- `true` / `false` と数字は、引用符で囲みません（`"level": 1`。`"level": "1"` は誤り）。
- 表にない項目名を書くとエラーになります。綴りの間違い（例：`pronounciation`）を見つけるためです。
- ハングルは普通に入力した文字で書きます。字母（ㅋ ㅓ ㅍ ㅣ）を並べた形にはしません。プログラムはUnicode正規化（NFC）された文字かどうかを確かめます。
  - ただし、ハングルのレッスン（14章）の `jamo`・`sound`・`letters`・`confusableWith` には字母を1つずつ書きます。説明の文（`introJa`・`tipJa`・`explanationJa`）の中でも、字母を使ってかまいません。

## 3. ID の決まり

- **一度ゲームに入れたIDは、後から変えたり使い回したりしません。** セーブデータと学習記録がIDで教材を参照しているためです。不要になった教材は削除してよいですが、そのIDは二度と使いません。
- **会話を作り直すときも、新しいIDにします。** 学習記録は「会話ID＋何往復目か」で付けているため、同じIDのまま往復の数や順番を変えると、記録がずれます。誤字の修正や、訳・読みの直しは、同じIDのままでかまいません。
- 単語・文法・会話・コラム・ハングルのレッスン・読む練習の単語・リスニングの文・基礎ドリル・章末テスト・ドリルとテストの問題・聞き分けの組・おはなし・読み物・メニュー・注文のIDは、種類を通して重複できません。別のファイルにあっても重複はエラーになります。
- 番号は3桁以上にします（`001`、`002` … `999`、`1000`）。
- **900番台（`vocab_901` など）は、プログラムの仮データ用に予約しています。** 本番の教材では使わないでください。

| 種類 | 形式 | 例 |
|---|---|---|
| 単語 | `vocab_番号` | `vocab_001` |
| 文法 | `grammar_番号` | `grammar_001` |
| 会話 | `英小文字の名前_番号`（施設ID＋番号を推奨） | `cafe_001`、`convenience_store_001` |
| コラム | `column_番号` | `column_001` |
| イベント | `event_番号` | `event_001` |
| ハングルのレッスン | `hangul_番号` | `hangul_001` |
| 読む練習の単語（レッスンの `words`） | `hword_番号` | `hword_001` |
| リスニングの文 | `listen_番号` | `listen_001` |
| 基礎ドリル | `drill_番号` | `drill_001` |
| 章末テスト | `test_番号` | `test_001` |
| ドリル・テストの問題（`items` の各要素） | `dq_番号`（ドリルとテストで通し番号） | `dq_001` |
| 聞き分けの組 | `ear_番号` | `ear_001` |
| おはなし | `story_番号` | `story_001` |
| 読み物 | `reading_番号` | `reading_001` |
| メニュー | `menu_番号` | `menu_001` |
| 注文 | `order_番号` | `order_001` |

## 4. 読み（カタカナのフリガナ）の決まり

韓国語の文には、カタカナの読みを付けます。ゲームでは、韓国語の上に**区切り（空白）ごと**にフリガナとして表示します。

- **韓国語と同じ位置で、半角スペースを1つ入れて区切ります。** 区切りの数が韓国語と違うとエラーになります。
  - 例：`아메리카노 한 잔 주세요.` → `アメリカノ ハン ジャン ジュセヨ`（どちらも4つ）
  - 韓国語の句読点は、前の語といっしょに1つの区切りとして数えます（`안녕하세요.` で1つ）。
- 読みに使える文字は、**カタカナ（ー を含む）と半角スペースだけ**です。句読点・ひらがな・全角スペースは入れません。先頭と末尾に空白を入れず、空白を2つ続けません。
- カタカナの書き方（連音化・濃音の「ッ」など）は docs/CONTENT_STYLE.md の1章に従います。

| 読みの項目 | 付ける場所 |
|---|---|
| `pronunciation` | 単語の見出し語、文法の例文、会話の台詞・選択肢・反応（`reply`）、コラムの韓国語、ハングルのレッスンの音節・単語・音の変化の例、リスニングの文、ドリル・テストの問題、聞き分けの組の音（`items`）、おはなしの台詞・看板・選択肢、読み物の本文と韓国語の選択肢、メニューの単位、注文の数・言い方、`glosses` の語句（`vocab` がないとき）、単語の元の形と形が変わった言葉、図の比べるもの |
| `pricePronunciation` | メニューの品物の値段（単位まで含めて区切りなし） |
| `resultPronunciation` | 図（`formation`）のくっついた形 |
| `examplePronunciation` | 単語の例文 |

書く問題の正解（`freeAnswer.answers`、読み物の `answers`）と別解（`alternatives`）は、プレイヤーが書く答えなので読みを付けません。

## 5. 共通の項目

すべての単語・文法・会話・コラム・ハングルのレッスン・リスニングの文・基礎ドリル・章末テスト・聞き分けの組・おはなし・読み物・メニュー・注文に付けます（レッスンの中の `words` と、ドリル・テスト・聞き分けの組の中の `items` には `reviewed` を付けず、まとめて示します）。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | 一意のID（3章） |
| `reviewed` | 必須 | true / false | 韓国語を確認済みか。作ったときは `false` にし、別のAIや韓国語母語話者の確認が済んだら `true` にする |
| `notes` | 任意 | 文字列 | 確認者のメモ（確認した人・日付・気になった点など） |

## 6. 単語

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 韓国語（見出し語）。正解判定では、これが模範解答になる |
| `alternatives` | 任意 | 文字列の配列 | 正解として認める別表記（例：`짜장면` に対する `자장면`）。1個以上入れる。`korean` と同じものは入れない |
| `pronunciation` | 必須 | 文字列 | 見出し語の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `partOfSpeech` | 必須 | キー | 品詞（10-1のキー一覧から選ぶ） |
| `genre` | 必須 | キー | ジャンル（10-2のキー一覧から選ぶ）。図鑑のタブになる |
| `level` | 必須 | 整数（1以上） | 難しさ。1がいちばんやさしい |
| `example` | 任意 | 文字列 | 例文（韓国語） |
| `examplePronunciation` | 任意 | 文字列 | 例文の読み（4章） |
| `exampleJapanese` | 任意 | 文字列 | 例文の日本語訳 |
| `base` | 任意 | オブジェクト | 元の形（辞書の形）。見出し語が元の形でないときに書く（24章） |
| `forms` | 任意 | 配列（1個以上） | 形が変わった言葉（해요の形・過去の形・縮んだ形など。24章） |

- 例文の3項目（`example`・`examplePronunciation`・`exampleJapanese`）は、**3つそろえて書くか、3つとも省きます。**
- 空白の違い（分かち書き）と、句読点（. , ? !）、全角・半角の違いは、判定のときにプログラムが吸収します。そのため、こうした違いだけの別表記を `alternatives` に入れる必要はありません。
- 意味は同じでも別の単語（類義語）は、原則として `alternatives` に入れません。入れる場合は、`notes` に理由を書いてください。
- 単語の問題（韓国語→日本語・日本語→韓国語・聞いて選ぶ・文字の並べ替え・例文の穴埋め・日本語を見て書く）は、プログラムが作ります。例文の穴埋めは、`example` の中に `korean` がそのままの形で入っているときだけ出します。

## 7. 文法

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `title` | 必須 | 文字列 | 文法の名前（例：`이에요 / 예요`） |
| `level` | 必須 | 整数（1以上） | 難しさ |
| `explanation` | 必須 | 文字列 | 日本語での説明。初心者に分かる簡単な言葉で書く |
| `connectionJa` | 任意 | 文字列 | 接続ルールの説明（日本語。例：「名詞の最後にパッチムがあれば 이에요、なければ 예요」）。説明のためにハングルを入れてよい。文法カードに表示する |
| `examples` | 必須 | 配列（1個以上） | 例文。各要素は下の表のとおり |
| `figures` | 任意 | 配列（1個以上） | 文法カードに添える図や絵（23章） |

`explanation` と `connectionJa` は、先生が話す形で出します（22章）。

`examples` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 例文（韓国語） |
| `pronunciation` | 必須 | 文字列 | 例文の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `alternatives` | 任意 | 文字列の配列 | 例文を答えさせる問題で、正解として認める別の言い方 |
| `blank` | 任意 | 文字列 | 穴埋め問題で隠す部分（例：`이에요`）。`korean` の中に**そのままの形で1回だけ**出てくる部分にする。文全体は不可 |
| `blankWrong` | `blank` があれば必須 | 文字列の配列（1個以上） | 穴埋め問題のまぎらわしい選択肢（例：`예요`）。`blank` と同じものは入れない |

文法の問題は、プログラムが例文から作ります。
- **穴埋め**：`blank` のある例文だけで出します。`blank` を空欄にし、`blank` と `blankWrong` から選びます。接続ルール（이에요 と 예요 など）の練習になるよう、`blankWrong` には間違えやすい形を入れます。
- **並べ替え**：例文を空白で区切った語を並べ替えます（区切りが2つ以上ある例文だけ）。教材に書き足すものはありません。
- **日本語を見て書く**：`japanese` を見て例文を書きます。`korean` と `alternatives` を正解にします。

## 8. 会話

1つの会話は、1つ以上の**往復**（`turns`）でできています。1往復は「相手の台詞 → プレイヤーの返事 → 相手の反応」です。

```
往復1：台詞（lines）→ 返事（choices / freeAnswer）→ 反応（reply）
往復2：台詞（lines）→ 返事 → 反応
…
最後の往復：締めの台詞（lines）だけでもよい
```

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `chapter` | 必須 | 整数（1〜10） | 何章の会話か（GAME_SPEC 5章） |
| `location` | 必須 | キー | 会話する施設（10-3） |
| `character` | 必須 | キー | 会話の相手（10-4。`player` は使えない）。この人の立ち絵を表示する |
| `turns` | 必須 | 配列（1個以上） | 往復を順番に並べる（8-1） |

### 8-1. 往復（`turns` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `kind` | 任意 | `"decision"` | 選択の往復にするときだけ `"decision"` と書く（8-7）。問題の往復では書かない |
| `task` | 問題の往復では必須 | 文字列 | 何を言えばよいか（日本語。例：「コーヒーを注文しよう」）。選ぶ・書く・話すのどの画面でも「言うこと」として表示する。ハングルは入れない。選択の往復では任意 |
| `lines` | 下を参照 | 配列 | プレイヤーが答える前の台詞（8-2）。画面では1つずつ表示する |
| `choices` | 任意 | 配列 | 選んで答えるときの選択肢（8-4）。問題の往復では1個以上で、`"correct": true` を**ちょうど1つ**。選択の往復では2個以上 |
| `freeAnswer` | 任意 | オブジェクト | 書いて（話して）答えるときのお題と正解（8-5）。問題の往復にだけ書ける |

- **`choices` のある往復**が、プレイヤーが答える往復です。会話には1つ以上必要です。
- **`choices` のない往復**は、台詞だけの往復です。**会話の最後の往復（締めの台詞）にだけ**使えます。`lines` を1つ以上入れます。`kind`・`task` は書けません。
- `lines` は、**最初の往復では必須**（1つ以上）です。2つ目以降の、`choices` のある往復では省略できます（前の往復の反応 `reply` が、そのまま次の質問になっている場合など）。
- 経験値と学習記録は、問題の往復ごとに付きます（選んで正解・書いて正解、それぞれ初めてのときだけ）。正解した問題の往復は、復習にも入ります。選択の往復には付きません。

### 8-2. 台詞（`lines` と `reply` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `speaker` | 必須 | キー | 話す人（10-4） |
| `korean` | 必須 | 文字列 | 台詞（韓国語） |
| `pronunciation` | 必須 | 文字列 | 台詞の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `expression` | 任意 | キー | 話すときの表情（10-6）。主人公（`player`）の台詞には付けられない |
| `glosses` | 任意 | 配列（1個以上） | タップで意味を見る語句のうち、自動でつながらないもの（21章） |

### 8-3. 表情（`expression`）

会話の相手（`character`）の立ち絵は、台詞に合わせて表情が変わります。

- 台詞に `expression` を書くと、**いつもその表情**になります。
- 書かなかったときは、プログラムが自動で決めます。

| 場面 | 自動で決まる表情 |
|---|---|
| ふだんの台詞（`lines`） | `normal`（通常） |
| プレイヤーが正解した直後と、その反応（`reply`） | `smile`（笑顔） |
| プレイヤーが間違えた直後と、間違えた選択肢の反応（`reply`） | `troubled`（困り顔） |
| 「答えを見る」で進んだ直後と、その反応 | `normal` |

- 相手以外（主人公など）が話している間は、直前の相手の表情のままです。
- 自動の表情と違う顔にしたいときだけ、`expression` を書けば十分です（例：正解の反応でも、驚いた・困った返事なら `"expression": "troubled"`）。

### 8-4. 選択肢（`choices` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 選択肢（韓国語）。同じ往復の中で重複させない |
| `pronunciation` | 必須 | 文字列 | 選択肢の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳。間違えたときに「〜という意味です」と表示するのにも使う |
| `correct` | 問題の往復では必須 | true / false | 正解か。問題の往復では、`true` をちょうど1つにする。選択の往復では書かない |
| `reply` | 下を参照 | 配列（1個以上） | この選択肢を選んだときの相手の反応（台詞。8-2）。1つずつ表示する |

- **正解の選択肢の `reply`**（任意）：主人公の返事の後に表示し、次の往復へ進みます。書かなかった場合は、すぐ次の往復へ進みます。
- **不正解の選択肢の `reply`**（必須）：「〜という意味です。もう一度選んでみましょう」の案内と一緒に表示し、プレイヤーはもう一度選びます（例：店を出るあいさつを選ぶと、店員が「네?」と聞き返す）。困った顔・聞き返すなど、相手が反応するようにします（GAME_SPEC 4-4）。
- **選択の往復の `reply`**（必須）：選んだものに合わせた反応です。表示した後、次の往復へ進みます。
- 不正解の選択肢は、初心者が間違えやすいものにします（場面に合わないあいさつ、似た音の言葉など。CONTENT_STYLE 3章）。

### 8-5. 書いて答える（`freeAnswer`）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `prompt` | 必須 | 文字列 | 日本語のお題（例：「コーヒーをください」） |
| `answers` | 必須 | 文字列の配列（1個以上） | 正解。**先頭が模範解答**で、2つ目以降が別解。自然な言い方が複数ある場合は、すべて入れる |
| `reply` | 任意 | 配列（1個以上） | 書いて正解したときの相手の反応（8-2） |

- `prompt` は `task` と同じ内容にします（`task` が「何を言うか」、`prompt` が「どう言うか」の日本語。例：`task`「コーヒーを注文しよう」、`prompt`「コーヒーをください」）。
- 書いて正解したときの反応は、次の順で決まります：`freeAnswer.reply` → 書いた答えと同じ文の選択肢の `reply` → 正解の選択肢の `reply`。

### 8-6. 書くときの目安

- 丁寧語とタメ口の使い分けは docs/CONTENT_STYLE.md の2章に従います。
- 1つの会話の中の往復は、同じ場面のひと続きのやりとりにします。場面が変わるとき（店に入る → 席に着く など）は、別の会話にしてイベント（11章）で並べます。

### 8-7. 問題の往復と選択の往復（GAME_SPEC 4-4）

| | 問題の往復（`kind` を書かない） | 選択の往復（`"kind": "decision"`） |
|---|---|---|
| 使う場面 | 言うべきことが決まっている（あいさつする、お礼を言う、注文する） | 選んだ内容で話が変わるだけ（ケーキも頼むか、はい・いいえのどちらで答えてもよい質問） |
| `task` | 必須（例：「お礼を言おう」） | 任意（例：「ケーキも頼むか決めよう」） |
| 選択肢 | 正解（`"correct": true`）がちょうど1つ。不正解には `reply` が必須 | `correct` を書かない。2個以上で、すべてに `reply` が必須 |
| 書く・話す（`freeAnswer`） | 書ける | 書けない（選ぶだけ） |
| 経験値・学習記録・復習 | あり | なし（「声に出して言ってみる」の練習はできる） |

- 選択の往復は、相手の反応（`reply`）だけが変わります。その後の往復は、どれを選んでも同じです。
- 好きなものを自由に注文する場面は、「注文」（書く・話す専用。27章）で作ります。

## 9. コラム（韓国生活の小ネタ）

イベントの途中で、韓国での暮らしに役立つ小ネタを読む画面です。経験値は付きません。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `chapter` | 必須 | 整数（1〜10） | 何章のコラムか（フリガナをいつも出すかどうかの判定に使う） |
| `titleJa` | 必須 | 文字列 | 見出し（日本語。ハングルは入れない） |
| `blocks` | 必須 | 配列（1個以上） | 本文。上から順に表示する。各要素は下の表のどちらか |

`blocks` の各要素：

| `type` | ほかの項目 | 意味 |
|---|---|---|
| `text` | `textJa`（必須） | 日本語の文。**ハングルは入れない** |
| `korean` | `korean`・`pronunciation`・`japanese`（すべて必須） | 韓国語の語句や文。フリガナと読み上げボタンを付けて表示する。読みは4章の決まりに従う |

- 韓国語を見せたいときは、日本語の文の中に書かず、`korean` のブロックに分けます（読みと確認済みの印を付けるため）。
- 短く読めるように、`text` のブロックは2〜4個くらいを目安にします。

### 10-4. キャラクターID・話者ID（会話の `character` と `speaker`）

| キー | 人物 | 名前 | `character` に使える | `speaker` に使える |
|---|---|---|---|---|
| `friend` | キャラクターA：近所の友人 | 윤하나（ユンハナ） | ○ | ○ |
| `cafe_staff` | キャラクターB：カフェの店員 | 한지훈（ハンジフン） | ○ | ○ |
| `neighbor` | キャラクターC：近所の住人 | 이수진（イスジン） | ○ | ○ |
| `teacher` | キャラクターD：先生（オンラインの家庭教師） | 정민호（チョンミノ） | ○ | ○ |
| `taxi_driver` | タクシーの運転手（立ち絵なし） | － | ○ | ○ |
| `airport_staff` | 空港の係員（立ち絵なし） | － | ○ | ○ |
| `announcement` | 館内放送（立ち絵なし） | － | ○ | ○ |
| `player` | 主人公（プレイヤー） | － | × | ○ |

- 윤하나：20代半ばの会社員で、近所に住んでいる。明るくておしゃべり、好奇心旺盛。最初は丁寧語で話す（GAME_SPEC 2-3）。
- 한지훈：20代半ば。落ち着いていて、接客は丁寧。実は甘いものに目がない。
- 이수진：30代後半。主人公の家の隣に住んでいる。穏やかで面倒見がよく、料理が得意。
- 정민호：40代前半。オンラインの家庭教師で、日本語が話せる。穏やかでほめ上手。親父ギャグが好き（GAME_SPEC 2-3）。
- 間違えたときの接し方（キャラクターの決まり。不正解の選択肢の `reply`、おはなしの選択の反応などに使います）：
  - 윤하나（`friend`）は、間違いを**明るく笑って**伝えます。引いたり困ったりせず、「하하」「아하하」などと笑いながら、何が違ったのかが分かる言い方にします。表情は `smile` にします（例：하하, 그건 헤어질 때 하는 말이에요!）。
  - 정민호（`teacher`）は、間違いに**優しく**接します。責めたり、がっかりした様子を見せたりせず、惜しかったところや正しい言い方を穏やかに伝えます。
  - どちらも、反応の中で正しい答えをそのまま言わせる形にはしません（同じ往復で、もう一度選ぶ問題の答えになってしまうため）。
- 立ち絵のない人物は、名札だけで台詞を出します（おはなし・会話のどちらでも使えます）。ほかに必要な人物がいれば、教材を作る前に開発者に伝えてください。
- 名前・人物像の元の案は docs/ART_GUIDE.md の3-3・3-4、話し方は docs/CONTENT_STYLE.md の2章にあります。
- IDは役割を表す名前のまま変えません。
- 施設・キャラクターを追加したいときは、教材を作る前に開発者に伝えてください。プログラム側のデータ（`src/data/locations/`、`src/data/characters/`）への追加が必要です。

## 11. イベント

イベントは「どの施設で、何を、どの順に行うか」を決めるデータです。教材とあわせて下書きしてください。プレイヤーは、前提のイベントを終えた後に、その施設で「`actionJa`」のボタンを押してイベントを始めます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `event_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章のイベントか。フリガナをいつも出すかどうかの判定にも使う |
| `location` | 必須 | キー | イベントが起きる施設（10-3） |
| `requires` | 必須 | 文字列の配列 | 先に終えておくイベントのID。最初のイベントは `[]` |
| `objectiveJa` | 必須 | 文字列 | 目標として画面の上に出す文（例：「カフェで注文してみよう」） |
| `actionJa` | 必須 | 文字列 | 施設の画面に出す、イベントを始めるボタンの文字（例：「カウンターへ行く」） |
| `start` | 任意 | `"auto"` | ボタンを押さなくても始まる（19-2） |
| `unlocks` | 任意 | 文字列の配列（1個以上） | 終えたら行けるようになる施設のID（19-2） |
| `steps` | 必須 | 配列（1個以上） | 段階を順番に並べる（10-5） |
| `notes` | 任意 | 文字列 | メモ |

**決まり**
- **日本語の文（`objectiveJa`・`actionJa`・`textJa`）には、ハングルを入れません。** 韓国語を見せたいときは、単語・文法・会話・コラムの教材として作り、`learn`・`conversation`・`column` で使います。
- `conversation` で使う会話と `order` で使う注文は、イベントと同じ施設のものにします。1つの会話・おはなし・読み物・注文は、1つのイベントでしか使えません。
- `chapter` は、章の一覧（19-1）にある章にします。
- 単語は、その単語が初めて出てくる会話より前の `learn` で覚えるようにします。1度に覚える単語は、5〜7語くらいまでを目安にします。
- `requires` に書いたイベントが存在しない場合や、前提が循環している場合はエラーになります。
- 同じ施設で始められるイベントが複数あるときは、ファイルの中で先に書いたものから始まります。

### 11-1. 背景を切り替える（`background`）

イベントの途中で、背景を施設のふだんの背景から別の絵に切り替えられます（例：自宅のイベントで、玄関に出てお隣さんと話す場面）。

```json
"steps": [
  { "type": "message", "textJa": "玄関のチャイムが鳴りました。" },
  { "type": "background", "id": "entrance" },
  { "type": "learn", "vocabulary": ["vocab_001"] },
  { "type": "conversation", "id": "home_003" },
  { "type": "background", "id": "home" },
  { "type": "column", "id": "column_001" }
]
```

- 切り替えた背景は、次の `background` の段階か、イベントの終わりまで続きます。間にある `learn`・`message`・`column` なども、その背景のまま表示します（会話ごとに部屋と玄関を行き来しないようにするため）。
- 元の背景に戻すときは、施設ID（上の例では `home`）を書きます。
- `background` の段階は画面に何も出さず、すぐ次の段階に進みます。イベントの最後の段階には置けません（イベントが終わると、施設のふだんの背景に戻るため）。
- 背景の画像がまだない場合は、施設のふだんの背景のまま進みます。

## 14. ハングルのレッスン（GAME_SPEC 4-1）

ハングルを読めない人のための導入です。プレイヤーは自宅の「勉強する」→「ハングル」でレッスンを選びます。どのレッスンも最初から選べ、おすすめの順番（`order`）で並びます。

レッスンの中の問題は、プログラムが教材から**自動で作ります**。教材側で問題を1問ずつ書く必要はありません。

1. 文字を見る・聞く（`introJa`、文字ごとの `tipJa` と聞かせる音節 `sounds`）
2. 聞いて文字を選ぶ／文字を見て読み（カタカナ）を選ぶ
3. ゲーム内キーボードで音節を組み立てる
4. 単語を読む（`words`・`vocabulary`）
5. 小テスト（合格すると完了の印が付く）

- 読む練習の単語（`words`）は、図鑑には入りません（レッスンの中だけで使います）。
- 端末に韓国語の音声がないときは、「聞いて選ぶ」問題を、聞かせる音節のカタカナを見て選ぶ問題に置き換えます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `order` | 必須 | 整数（1以上） | 並び順。ほかのレッスンと重複できない。**習った文字の範囲**（14-6）もこの順で決まる |
| `kind` | 必須 | キー | レッスンの種類（10-8） |
| `titleJa` | 必須 | 文字列 | レッスンの名前（日本語。**ハングルは入れない**。一覧に表示する） |
| `introJa` | 必須 | 文字列の配列（1個以上） | 導入の説明。1要素が1段落。字母やハングルを入れてよい。先生が話す形で出す（22章） |
| `figures` | 任意 | 配列（1個以上） | 導入の説明の後に出す図や絵（23章） |
| `letters` | 下を参照 | 配列（1個以上） | 覚える文字（14-1）。`kind` が `letters` のときだけ書く |
| `finals` | 下を参照 | 配列（1個以上） | パッチムのグループ（14-3）。`kind` が `batchim` のときだけ書く |
| `rules` | 下を参照 | 配列（1個以上） | 音の変化のルール（14-4）。`kind` が `soundChange` のときだけ書く |
| `words` | 下を参照 | 配列（1個以上） | 読む練習の単語（14-5） |
| `vocabulary` | 下を参照 | 文字列の配列 | 読む練習に使う、教材の単語のID（`vocab_001` など）。`kind` が `reading` のときだけ書ける。見出し語（`korean`）を読む |

どの項目を書くかは `kind` で決まります（10-8 の表）。表にない項目を書くとエラーになります。

### 14-1. 文字（`letters` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `jamo` | 必須 | 字母1つ | 覚える字母（例：`ㄱ`、`ㅏ`）。子音19個・母音21個のどれか。**ほかのレッスンと重複できない** |
| `sounds` | 必須 | 配列（1個以上） | 聞かせる音節（14-2） |
| `tipJa` | 必須 | 文字列 | 発音のこつ（日本語）。日本語の音との違い、口の形など |
| `confusableWith` | 任意 | 字母の配列 | まぎらわしい字母（例：`ㅓ` に対する `ㅗ`）。「聞いて選ぶ」問題で選択肢に混ぜる。自分自身は入れない |
| `figures` | 任意 | 配列（1個以上） | 文字に添える図や絵（23章。口の形など） |

### 14-2. 聞かせる音節（`sounds` の各要素）

字母（ㄱ など）をそのまま読み上げると、「기역」のように**字母の名前**で読まれてしまいます。そのため、音は**音節**で聞かせます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 1音節 | 読み上げる音節（例：`가`） |
| `pronunciation` | 必須 | 文字列 | その音節の読み（カタカナ。空白なし） |

- **母音**：文頭に ㅇ を付けた音節にします（ㅏ → `아`）。パッチムは付けません。
- **子音**：その子音で始まる音節を2〜3個にします（ㄱ → `가`・`고`・`구`）。いろいろな母音と組み合わせると、子音の音を聞き分けやすくなります。パッチムは付けません。
- **パッチム**（14-3）：パッチムのある音節にします（ㄱ のグループ → `악`）。
- 1つ目の音節が、その文字のいちばん大事な音です（一覧や小テストで最初に使います）。
- 読み（カタカナ）は、端末に韓国語の音声がないときの置き換え問題にも使います。

### 14-3. パッチムのグループ（`finals` の各要素）

パッチムは、発音が7つの代表音（ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅇ）のどれかになります。代表音ごとに1つのグループにします。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `sound` | 必須 | 字母1つ | 代表音（`ㄱ` `ㄴ` `ㄷ` `ㄹ` `ㅁ` `ㅂ` `ㅇ` のどれか） |
| `letters` | 必須 | 字母の配列（1個以上） | この音になるパッチムの字母（例：ㄱ のグループなら `ㄱ` `ㅋ` `ㄲ`）。二重パッチム（`ㅄ` など）も入れられる。**同じ字母を2つのグループに入れない** |
| `sounds` | 必須 | 配列（1個以上） | 聞かせる音節（14-2）。パッチムが `letters` のどれかの音節 |
| `tipJa` | 必須 | 文字列 | 発音のこつ |
| `figures` | 任意 | 配列（1個以上） | 図や絵（23章。舌や唇の位置など） |

- **パッチムは、ここで `letters` に入れた字母だけが「習った」ことになります**（14-6）。後のレッスンで使う言葉のパッチム（二重パッチムを含む）は、どれかのグループに入れておいてください。
- 二重パッチムは、概要を `introJa` で説明し、よく出るもの（없어요 の `ㅄ` など）を、読む音のグループの `letters` に入れます。

### 14-4. 音の変化のルール（`rules` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `titleJa` | 必須 | 文字列 | ルールの名前（例：「連音化」。ハングルは入れない） |
| `explanationJa` | 必須 | 文字列 | 説明（日本語。字母やハングルを入れてよい） |
| `examples` | 必須 | 配列（1個以上） | 例（下の表）。3〜4個が目安 |
| `figures` | 任意 | 配列（1個以上） | 図や絵（23章） |

`examples` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 書いた形（例：`음악`）。これを読み上げる |
| `spoken` | 必須 | 文字列 | 発音どおりにハングルで書いた形（例：`으막`）。`[으막]` のように表示する。`korean` と同じ位置で空白を入れる |
| `pronunciation` | 必須 | 文字列 | 読み（4章。発音どおりのカタカナ） |
| `japanese` | 必須 | 文字列 | 意味 |

- 読み上げは、書いた形（`korean`）をそのまま読ませます。ふつうは、音の変化をした正しい発音で読まれます。

### 14-5. 読む練習の単語（`words` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `hword_番号`（3章）。ほかの教材のIDと重複できない |
| `korean` | 必須 | 文字列 | 韓国語 |
| `pronunciation` | 必須 | 文字列 | 読み（4章） |
| `japanese` | 必須 | 文字列 | 意味 |

- 1レッスンに**4〜8語**が目安です。プログラムは1語以上あればよいとしています（母音だけのレッスンでは、書ける単語が少ないため）。
- 同じレッスンの中で、同じ韓国語を2回入れないでください。

### 14-6. 習った文字の範囲（プログラムが確かめること）

レッスンの中の韓国語（聞かせる音節・`words`・音の変化の例・`vocabulary` の単語）は、**そのレッスンまでに習った文字だけ**で書けていなければなりません。書けていないとエラーになり、そのレッスンは読み込まれません。

- 「そのレッスンまで」とは、`order` がそのレッスン以下のレッスンのことです（そのレッスン自身を含む）。
- **文字**：`letters` のレッスンの `jamo` で習ったものが使えます。複合母音（ㅘ など）は、その複合母音として習ったものだけが使えます（ㅗ と ㅏ を習っただけでは使えない）。
- **文頭の ㅇ**：音がない文字なので、どのレッスンでも使えます（母音のレッスンで `아이` などを書けるようにするため）。
- **パッチム**：`batchim` のレッスンの `finals` の `letters` に入れたものだけが使えます。**パッチムのレッスンより前のレッスンでは、パッチムのある言葉はエラーになります**（例：子音のレッスンで `수박` は使えない）。パッチムの ㅇ（`방` など）も同じです。

### 14-7. レッスンの分け方（Phase 2 の予定）

全部で12本です。1度に覚える文字は5〜7個までを目安にしています。

| `order` | `kind` | レッスン | 覚えるもの |
|---|---|---|---|
| 1 | `letters` | 基本の母音（1） | ㅏ ㅓ ㅗ ㅜ ㅡ ㅣ |
| 2 | `letters` | 基本の母音（2） | ㅑ ㅕ ㅛ ㅠ |
| 3 | `letters` | 基本の子音（1） | ㄱ ㄴ ㄷ ㄹ ㅁ（有声音化の説明を含む） |
| 4 | `letters` | 基本の子音（2） | ㅂ ㅅ ㅇ ㅈ ㅎ（有声音化の説明を含む） |
| 5 | `letters` | 激音 | ㅊ ㅋ ㅌ ㅍ |
| 6 | `letters` | 濃音 | ㄲ ㄸ ㅃ ㅆ ㅉ |
| 7 | `letters` | 複合母音（1） | ㅐ ㅔ ㅒ ㅖ ㅘ ㅝ |
| 8 | `letters` | 複合母音（2） | ㅙ ㅞ ㅚ ㅟ ㅢ |
| 9 | `batchim` | パッチム | 7つの代表音のグループ。二重パッチムの概要と、よく出るもの3〜4個 |
| 10 | `soundChange` | 音の変化（1） | 連音化・ㅎの弱化・激音化 |
| 11 | `soundChange` | 音の変化（2） | 鼻音化・濃音化・口蓋音化 |
| 12 | `reading` | 第1章の言葉を読む | 教材の単語（`vocabulary`）を読む |

- 有声音化（語中で「カ」が「ガ」のように濁る）は、子音のレッスン（3・4）の `introJa` か `tipJa` で説明します。
- 流音化は、Phase 3 以降で必要になったら足します。
- 第1章の言葉を読むレッスン（12）では、`vocabulary` に入れた単語の見出し語も、習った文字の範囲を確かめます。二重パッチムなどがあれば、9 の `finals` に入れておいてください。

**必要な数の目安**

| 種類 | 数 |
|---|---|
| レッスン | 12本（導入の説明は各2〜4段落） |
| 文字（`letters`） | 40字（母音21・子音19） |
| パッチムのグループ（`finals`） | 7グループ |
| 聞かせる音節（`sounds`） | 母音は各1個、子音は各2〜3個、パッチムは各グループ1〜2個 |
| 読む練習の単語（`words`） | 各レッスン4〜8語、合計50〜80語 |
| 音の変化の例 | 6ルール×3〜4例、合計18〜24例 |

### 14-8. 書くときの目安

- カタカナが同じになる字母（ㅓ と ㅗ、ㅐ と ㅔ など）は、`tipJa` で違いを説明し、`confusableWith` にお互いを入れます。プログラムは、カタカナを選ぶ問題では、同じカタカナの選択肢を一緒に出しません。
- `words` には、なるべく実際によく使う言葉を選びます。意味のない音の並びは避けます。
- レッスンの `reviewed` は、レッスン全体（説明・音節・単語・例）を確認してから `true` にします。

## 15. リスニングの文（GAME_SPEC 4-5）

学習画面の「リスニング」で出す「聞いて正しい文を選ぶ」問題です。正解の文を読み上げ、正解の文とまぎらわしい文の中から選ばせます。答えた後に、それぞれの文の意味を表示します。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `afterEvent` | 必須 | 文字列 | このイベント（`event_001` など）を終えたら出題する。フリガナの表示も、このイベントの章に合わせる |
| `korean` | 必須 | 文字列 | 正解の文（読み上げる文） |
| `pronunciation` | 必須 | 文字列 | 読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `distractors` | 必須 | 配列（1個以上） | まぎらわしい文。各要素は `korean`・`pronunciation`・`japanese`（すべて必須）。2つが目安 |

- まぎらわしい文は、**聞き間違えやすい文**にします（同じ単語で語尾が違う、似た音の単語に入れ替える など）。意味がまったく違う文だと、聞かなくても選べてしまいます。
- 正解の文と、空白（分かち書き）や句読点の違いだけの文は、聞いても区別できないので使えません（エラーになります）。
- 文に使う単語・文法は、`afterEvent` のイベントまでに覚えたものにします。
- Phase 2 では、1日目のイベント（`event_001` の自宅、`event_002` のカフェ）の内容から **8〜10問**が目安です。
- 「聞いて単語を選ぶ」と「会話を聞いて返事を選ぶ」の問題は、覚えた単語と終えた会話から自動で作るので、教材はいりません（返事を選ぶ問題は、問題の往復の正解の選択肢から作ります。選択の往復は使いません）。

## 16. 基礎ドリル（GAME_SPEC 4-9）

数字・曜日・値段など、毎日の暮らしで必ず使う基礎を、物語と関係なく練習するためのテーマです。学習画面からいつでも選べます。
1つのドリルは1つのテーマで、問題（`items`）を並べたものです。**問題の形（選ぶ・聞く・書く）はプログラムが決める**ので、1問ごとに「韓国語と、その意味」を書きます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `drill_番号`（3章） |
| `titleJa` | 必須 | 文字列 | テーマの名前（日本語。例：「数字（漢数詞）」）。ハングルは入れない |
| `introJa` | 任意 | 文字列 | 始める前に見せる説明（日本語）。説明のためにハングルを入れてよい（例：「일・이・삼 … は値段や日付に使う数え方です」） |
| `questionCount` | 任意 | 整数（1〜50） | 1回の問題数。省略したら10問。問題（`items`）より多いときは、`items` の数だけ出す |
| `items` | 必須 | 配列（4個以上） | 問題。各要素は下の表のとおり |
| `figures` | 任意 | 配列（1個以上） | 説明に添える図や絵（23章） |
| `reviewed`・`notes` | | | 5章 |

`introJa` は、先生が話す形で出します（22章）。

### 16-1. 問題（`items` の各要素。章末テストの `items` も同じ形）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `dq_番号`。ドリルとテストをまたいで一意にする（復習の記録がこのIDで参照するため） |
| `korean` | 必須 | 文字列 | 韓国語（模範解答） |
| `alternatives` | 任意 | 文字列の配列（1個以上） | 正解として認める別の言い方（例：`하나` に対する `한 개`）。`korean` と同じものは入れない。**韓国語（ハングル）で書く**（数字だけの別解は入れられない） |
| `pronunciation` | 必須 | 文字列 | `korean` の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語。数字の問題では、画面に出す数の書き方（例：`3,500ウォン`、`3時30分`）。ハングルは入れない |
| `digits` | 任意 | 文字列 | **数字の問題にするときだけ**書く。プレイヤーが入力する数字（半角。例：`3500`）。時刻・日付は `:` と `/` で区切る（例：`3:30`、`5/15`）。カンマや単位は入れない |
| `hintJa` | 任意 | 文字列 | 問題に添えるひとこと（日本語。例：「固有数詞で」）。ハングルは入れない |

### 16-2. 出題のしかた（プログラムが決めること）

- **数字の問題**（`digits` あり）：選択肢は出しません（選択肢がヒントになるため。GAME_SPEC 4-2）。
  - 韓国語を見て（または聞いて）、数字を入力する → `digits` と比べます。
  - 日本語（`japanese`）を見て、韓国語をゲーム内キーボードで入力する → `korean` と `alternatives` だけを正解にします。**数字（`3500` など）で書いた答えは正解にしません**（読み方を書く練習のため）。
- **数字でない問題**（`digits` なし）：韓国語→日本語を選ぶ、日本語→韓国語を選ぶ、聞いて選ぶ（音声があるときだけ）、日本語を見て韓国語を書く、を混ぜます。
  - 選択肢は、**同じドリルのほかの問題**から作ります。そのため、1つのドリルには同じ種類のもの（曜日なら曜日だけ）を入れます。
- 間違えた問題は復習（GAME_SPEC 7-5）に入り、間隔を空けてもう一度出ます。

### 16-3. 書くときの目安

- 1テーマ **10〜20問**。
- 漢数詞と固有数詞は、**テーマを分けます**（「数字（漢数詞）」「数字（固有数詞）」）。1つのドリルに混ぜるときは、`hintJa` で「漢数詞で」「固有数詞で」と示します。
- 値段・時刻は、数字と単位を組み合わせた形にします（例：`삼천오백 원`、`세 시 삼십 분`）。読み（`pronunciation`）は CONTENT_STYLE 1章のとおり、実際の発音どおりに書きます。数と単位の間（空白をまたぐところ）の連音化も反映します（例：`삼천오백 원` → サムチョノベ グォン、`오백 원` → オベ グォン）。
- 固有数詞の数え方（`하나` と `한 개` など）、分かち書きのゆれ以外の別の言い方は、`alternatives` に入れます。空白の違いだけの別解は入れる必要はありません（プログラムが吸収します）。

## 17. 章末テスト（GAME_SPEC 4-9）

章の終わりに、その章の内容を確かめるテストです。**問題はプログラムが、その章の単語・文法・会話から自動で作ります。** 教材として書くのは、テストの名前・問題数・合格の基準と、足したい問題（任意）だけです。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `test_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章のテストか。**1つの章にテストは1つまで** |
| `titleJa` | 必須 | 文字列 | テストの名前（日本語。例：「第1章のテスト」）。ハングルは入れない |
| `questionCount` | 任意 | 整数（1〜50） | 問題数。省略したら10問 |
| `passPercent` | 任意 | 整数（0〜100） | 合格の基準（正解の割合）。省略したら80 |

- 自動で作る問題のもと：

## 18. 聞き分けの組（GAME_SPEC 4-10）

日本語話者が聞き分けにくい、似た音を聞く練習のための組です。組の中の1つを読み上げ、どれだったかを**同じ組の中から**選ばせます。どの組を作るかは、docs/STUMBLING_POINTS.md（つまずきリスト）の「聞き分け練習の最初の組」をもとに決めます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `ear_番号`（3章） |
| `theme` | 必須 | 文字列 | テーマ（10-9） |
| `titleJa` | 必須 | 文字列 | 組の名前（例：「ㅂ・ㅍ・ㅃ」）。聞き分ける字母を入れてよい |
| `focusJa` | 必須 | 文字列 | どこを聞き分けるか（例：「最初の子音の息の出方」）。組の一覧に出す |
| `tipJa` | 必須 | 文字列 | 聞き分けのこつ（1〜2文）。答えた後に出す。字母や単語を入れてよい |
| `stumbling` | 任意 | 文字列の配列（1個以上） | つまずきリストのID（例：`["S01"]`） |
| `items` | 必須 | 配列（2〜4個） | 組の音。各要素は下の表のとおり |
| `figures` | 任意 | 配列（1個以上） | こつに添える図や絵（23章。息の出方・口の形など） |
| `reviewed`・`notes` | | | 5章 |

`tipJa` は、先生が話す形で出します（22章）。

### 18-1. 組の音（`items` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 読み上げる単語（ハングル） |
| `pronunciation` | 必須 | 文字列 | 読み（4章）。組の中で同じカタカナになってもかまいません（불・풀 はどちらも「プル」） |
| `japanese` | 必須 | 文字列 | 意味。**1つに絞ります**（밤 は「夜」か「栗」のどちらか）。組の中で同じ意味は使えません。ハングルは入れない |

- 組の中で、同じ韓国語（空白・句読点の違いだけのものを含む）は使えません（エラーになります）。

### 18-2. 出題のしかた（プログラムが決めること）

- 組の中から1つを読み上げ、組の音をすべて選択肢にします（ほかの組の音は混ぜません）。読み上げる音は、組の中でほぼ同じ回数になるようにします。
- 選択肢には、答える前から韓国語と意味を出します。フリガナは、答えるまで出しません（同じカタカナになることが多く、まぎらわしいため）。
- 答えた後に、選んだ音と正解の音を聞き比べられるようにし、`tipJa` を出します。
- 間違えた組は、復習（GAME_SPEC 7-5）に入ります。

### 18-3. 書くときの目安

- **実在する短い単語**にします（1音節だけの読み上げは、端末ではっきりしないことがあるため）。
- 聞き分けるところ（`focusJa`）以外は、できるだけ同じ音にします（불・풀・뿔 は最初の子音だけが違う）。
- 同じ音で意味の違う言葉（눈＝目・雪 など）は、聞いても区別できないので、同じ組に入れません。
- 実機で聞き分けにくい組は使いません。ゲームの「試しに聞く」で、組ごとに確かめられます。

## 19. 章立てとイベントの解放条件（GAME_SPEC 5章・12章 Phase 3）

Phase 3 から、物語は「1日目」ではなく**章**で進みます。章の一覧は開発側のデータ（`src/data/chapters/chapters.json`）です。イベントの `chapter` は、この一覧にある章にします（ない章を書くとエラーになります）。

### 19-1. 章の一覧（`src/data/chapters/`）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `chapter` | 必須 | 整数（1〜10） | 章の番号。重ねない |
| `titleJa` | 必須 | 文字列 | 章の題（例：「韓国に到着」）。ハングルは入れない |
| `goalJa` | 必須 | 文字列 | できるようになること（GAME_SPEC 5章）。章の終わりの画面に出す。ハングルは入れない |

- 章を足す・題を変えるときは、開発者に伝えてください（教材の側で書くものではありません）。

### 19-2. イベントに足した項目

11章の表に、次の2つを足しました。どちらも任意です。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `start` | 任意 | `"auto"` | 前提（`requires`）を満たしたら、施設のボタンを押さなくても始まる。はじめからの直後の空港・タクシーなどに使う。ふだんは書かない |
| `unlocks` | 任意 | 文字列の配列（1個以上） | このイベントを終えたら行けるようになる施設のID（10-3）。例：`["cafe"]` |

- 最初から行ける施設は自宅だけにします。ほかの施設は、どこかのイベントの `unlocks` で開きます。
- `start: "auto"` のイベントでも `actionJa` は必須です（途中でやめたときに、施設の画面に「続きから」のボタンとして出すため）。

### 19-3. 新しい段階（`steps` の `type`）

10-5 の表に、次の段階を足しました。

| キー | 意味 | ほかの項目 |
|---|---|---|
| `story` | おはなしを1つ見る（20章） | `id`（おはなしのID。必須） |
| `reading` | 読み物を1つ読んで、問題に答える（25章） | `id`（読み物のID。必須） |
| `order` | メニューを見て、書く・話すで注文する（27章）。注文はイベントと同じ施設のものにする | `id`（注文のID。必須） |
| `listening` | このイベントのリスニングの文（15章。`afterEvent` がこのイベントのもの）を、その場で聞いて答える | なし |
| `chapterEnd` | 章の終わりの画面。その章で覚えた単語・会話のまとめと、章末テストの案内を出す。Phase 3 からは `dayEnd` の代わりに使う | `textJa`（必須。ひとこと） |
| `hangulIntro` | 「ハングルは読めますか？」と聞き、学ぶならハングルのレッスン1へ案内する。**ゲーム全体で1つだけ** | なし |

- 会話・おはなし・読み物・注文は、どれも**1つのイベントでしか使えません**（同じものを2つのイベントで使うとエラー）。
- `listening`・`hangulIntro`・`chapterEnd` は、1つのイベントに1つまでです。
- `listening` の段階で出したリスニングの文は、その後、学習画面の「リスニング」にも出ます。
- 章末テストは、次の章に進む条件にしません。`chapterEnd` の画面と学習画面から、いつでも受けられます。

## 20. おはなし（GAME_SPEC 3-2）

キャラクターとの会話劇や小さな物語を、紙芝居のように見せる場面です。正解・不正解はなく、読んで楽しむためのものです。イベントの `story` の段階で見せます。一度見たおはなしは、自宅の「おはなしのアルバム」から見返せます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `story_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章のおはなしか（フリガナをいつも出すかの判定と、アルバムの並びに使う） |
| `titleJa` | 必須 | 文字列 | おはなしの題（アルバムに出す。ハングルは入れない） |
| `bgm` | 任意 | キー | 始めに流す BGM（10-10）。省略したら、その場所の曲のまま |
| `beats` | 必須 | 配列（1個以上） | 段階を順番に並べる（20-1）。画面に出す段階（`narration`・`line`・`sign`・`choice`）を1つ以上入れる |
| `reviewed`・`notes` | | | 5章 |

### 20-1. 段階の種類（`beats` の `type`）

| キー | 意味 | ほかの項目 |
|---|---|---|
| `scene` | 場面を変える（20-2）。画面には何も出さず、すぐ次へ進む | `background`・`image`・`character`・`call`（どれか1つ以上） |
| `narration` | 地の文（日本語）。「……（あなたは名前を伝えた）」のような、主人公の動きや場面の説明 | `textJa`（必須。ハングルは入れない） |
| `line` | 台詞。項目は会話の台詞（8-2）と同じ | `speaker`・`korean`・`pronunciation`・`japanese`（必須）、`expression`・`glosses`（任意） |
| `sign` | 画面に出る韓国語の文字（空港の案内表示、看板、スマホの画面など）。読み・訳つきで見せる | `korean`・`pronunciation`・`japanese`（必須）、`glosses`（任意） |
| `choice` | 返事を選ぶ。正解・不正解はなく、選んだもので反応だけが変わる（20-3） | `choices`（必須。2個以上）、`promptJa`（任意。例：「どう返事する？」） |
| `sfx` | 場面の効果音を鳴らす（10-11） | `id`（必須） |
| `bgm` | BGM を変える（10-10）。`"none"` で止める | `id`（必須） |

### 20-2. 場面（`scene`）

書いた項目だけが変わり、書かなかった項目は前のままです。

| 項目 | 型 | 意味 |
|---|---|---|
| `background` | キー | 背景。場面の背景（10-7）か施設ID（10-3）。おはなしの最初は、イベントのそのときの背景 |
| `image` | キー または `null` | 一枚絵のキー（英小文字。画像は `cg_キー.png`）。`null` で消す。画像がまだないときは、背景だけで進む |

- 先生は、オンライン授業の場面では `call: "teacher"`、カフェで会う場面では `character: "teacher"`（ふつうの立ち絵）にします。

### 20-3. 台詞・看板・選択

- 台詞と看板の単語は、タップで意味を見られます（21章）。字が単語の教材と一致しない語句には `glosses` を書きます。
- 主人公の台詞は `"speaker": "player"` です。主人公の名前と性別は出しません（GAME_SPEC 2-2）。呼びかけにも名前を使いません。
- `choice` の `choices` の各要素：

| 項目 | 必須 | 型 | 意味 |

| `japanese` | 必須 | 文字列 | 日本語訳 |
| `reply` | 必須 | 配列（1個以上） | 選んだときの相手の反応（台詞。8-2） |

### 20-4. 書くときの目安

- 習った表現が自然に使われるようにします（GAME_SPEC 3-2）。
- 経験値・学習記録・復習はありません（タップして「覚える」を押した単語だけが復習に入ります）。

## 21. タップで意味を見る語句（`glosses`。GAME_SPEC 4-8）

おはなしの台詞と看板、読み物の本文、会話の台詞（`lines`・`reply`）では、単語をタップすると、読み・意味・読み上げを小さな窓で見られます。窓の「覚える」を押すと、図鑑の「見かけた単語」に入り、復習に加わります。会話の**選択肢**はタップできません（答えのヒントになるため）。

### 21-1. 自動でつながる語句（書かなくてよいもの）

台詞を空白で区切ったまとまり（前後の句読点は外します）が、次のどれかと**字がそのまま同じ**なら、プログラムが自動で単語の教材とつなぎます。

- 単語の見出し語（`korean`）・別表記（`alternatives`）
- 単語の元の形（`base.korean`）・形が変わった言葉（`forms` の `korean`。24章）

`안녕히 가세요` のように空白を含む見出し語は、続いたまとまりとして探します（長いものを先に探します）。単語の教材にあれば、まだ覚えていない単語でもつながります（窓には単語の教材の内容を出します）。

### 21-2. `glosses` に書くもの

自動でつながらない語句（助詞や語尾が付いた形、単語の教材にない語句）は、台詞ごとに `glosses` に書きます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `text` | 必須 | 文字列 | 台詞の中の語句。**空白で区切ったまとまりのまま**書く（1つ以上のまとまり。句読点は付けない）。例：`이름이 뭐예요?` なら `이름이` や `뭐예요`。まとまりの一部（`이름` だけ）は指せない |
| `vocab` | 下を参照 | 文字列 | つなぐ単語の教材のID。窓には単語の内容を出し、「覚える」で復習に加えられる |
| `pronunciation` | `vocab` がなければ必須 | 文字列 | 語句の読み（4章。`text` と同じ位置で空白を入れる） |
| `japanese` | `vocab` がなければ必須 | 文字列 | 語句の意味 |
| `noteJa` | 任意 | 文字列 | ひとこと（例：「이름（名前）＋이（〜が）」）。説明のためにハングルを入れてよい |

- `vocab` を書いたときは、`pronunciation`・`japanese` は書きません（単語の教材から出します）。
- `vocab` のない語句（人名・地名・一度しか出ない言葉など）は、窓で意味を見られますが、「覚える」は出ません（代わりに「名前やその場だけの言い方なので、図鑑には入りません」と出します）。復習させたい単語は、単語の教材（6章）に入れて `vocab` でつなぎます（`learn` の段階で教えなくてもかまいません）。
- 同じ台詞の中で、同じ `text` を2回書けません。

### 21-3. 書くときの目安

- 読み物では、知らない単語は**1文に1つまで**を目安にし、すべてに注釈を付けます。問題の答えが、注釈のない知らない単語に頼らないようにします（GAME_SPEC 4-8）。
- おはなしは日本語訳があるので、これより多くてもかまいません。物語の大事な単語には注釈を付けます。
- 学習の会話（8章）では、これまでどおり、新しい単語は使う前に `learn` で教えます。`glosses` は、覚えた単語に助詞が付いた形などを指すのに使います。

## 23. 図と絵（`figures`。GAME_SPEC 4-11）

説明の文だけでは分かりにくいところに、図や絵を添えます。文字・矢印・ハングルが入る図は、画像にせず、ゲームの画面の作りで描きます（AIで作った画像では文字が崩れるため）。

### 23-1. 図の種類（`figures` の各要素の `type`）

| キー | 意味 | ほかの項目 |
|---|---|---|
| `image` | 絵（口の形・舌の位置など。Gemini で作り、文字は入れない）。絵の上に札と矢印を重ねられる | `image`（必須）、`captionJa`・`labels`（任意） |

## 24. 形が変わる言葉（`base`・`forms`。GAME_SPEC 4-3）

動詞・形容詞は、語尾が付くと形が縮んだり（가＋아요 → 가요）、変わったり（춥다 → 추워요）します。話し言葉では、代名詞と助詞もくっつきます（저는 → 전）。単語（6章）に次の2つを書くと、単語カードと図鑑に元の形とよく出る形を並べ、「部品 → くっついた形」の図（23章の `formation`）で見せます。問題もプログラムが作ります。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `base` | 任意 | オブジェクト | 元の形（辞書の形）。**見出し語が元の形でないとき**に書く（例：見出し語 `주세요` に対する `주다`）。見出し語が元の形（`가다` など）なら書かない |
| `forms` | 任意 | 配列（1個以上） | 形が変わった言葉（下の表） |

`base` の項目：`korean`（必須）、`pronunciation`（必須。4章）、`japanese`（任意。元の形の意味が見出し語と違うとき。例：`주다` ＝「あげる・くれる」）。

`forms` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `kind` | 必須 | キー | 形の種類（10-12） |
| `korean` | 必須 | 文字列 | くっついた形（例：`가요`）。同じ単語の中で重ねない |
| `pronunciation` | 必須 | 文字列 | 読み（4章） |
| `parts` | 必須 | 文字列の配列（2個以上） | 部品（例：`["가", "아요"]`、`["저", "는"]`） |
| `wrong` | 任意 | 文字列の配列（1個以上） | 初心者が作りがちな誤った形（例：`가아요`、`춥어요`）。問題の不正解の選択肢に使う。`korean` と同じものは入れない |
| `noteJa` | 任意 | 文字列 | 説明（例：「ㅏ＋아요 は 아 が1つになります」）。ハングルを入れてよい |

**プログラムが作る問題**
- くっついた形から元の形を選ぶ（元の形は `base`、なければ見出し語。縮んだ形（`contraction`）は部品をつないだ形）
- 部品から正しい形を選ぶ（不正解には `wrong` と、ほかの単語の形を使う）
- 単語を `learn` で覚えると、その単語の形の問題も翌日から復習に出ます。間違えた問題は翌日の復習に戻ります。章末テストにも入ります。
- 復習の記録は「単語のID＋くっついた形」で付けます（例：`form:vocab_031#가요`）。**`korean` を後から直すと、その形の記録は使われなくなります**（復習は最初からになります）。

**書くときの目安**
- 見出し語が元の形の動詞・形容詞（`가다`、`맛있다`）には、よく出る形（`present`・`past`）を1〜2個書きます。
- 見出し語がくっついた形（`주세요`、`맛있어요`）のときは、`base` に元の形を書き、見出し語そのものも `forms` に入れて部品を示します。
- `wrong` は、つまずきリスト（V01〜）に出てくる誤りを中心にします。

## 25. 読み物（GAME_SPEC 4-7）

ある程度の長さの韓国語の文章を読んで、内容についての問題に答えます。イベントの `reading` の段階で使います。本文は読み上げでき、フリガナは設定（9-3）に従います。**日本語訳は、問題にすべて答えるまで隠します。** 経験値は、問題に初めて正解したときに付きます。復習には入りません（本文がないと解けないため）。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `reading_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章の読み物か |
| `titleJa` | 必須 | 文字列 | 題（例：「カフェのメニュー」）。ハングルは入れない |
| `style` | 必須 | キー | 見た目（10-13） |
| `lines` | `style` が `menu` でなければ必須 | 配列（1個以上） | 本文。1要素が1文（25-1） |
| `menu` | `style` が `menu` なら必須 | 文字列 | メニューのID（26章）。品物を、文字のメニューとショーケースに分けて出す（26章の `display`）。`menu` のときも、`lines` で説明の文を足せる |
| `questions` | 必須 | 配列（1個以上） | 問題（25-2）。上から順に出す |
| `reviewed`・`notes` | | | 5章 |

### 25-1. 本文（`lines` の各要素）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 1文（韓国語） |
| `pronunciation` | 必須 | 文字列 | 読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳（答え終わるまで隠す） |
| `glosses` | 任意 | 配列 | タップで意味を見る語句（21章） |

### 25-2. 問題（`questions` の各要素）

| 種類（`type`） | 意味 | ほかの項目 |
|---|---|---|
| `choice` | 選ぶ | `questionJa`（必須）、`choices`（必須。2個以上。`"correct": true` をちょうど1つ）、`explanationJa`（任意） |
| `number` | 数字を入れる（値段など。選択肢は出さない） | `questionJa`（必須）、`digits`（必須。半角数字。16-1 と同じ書き方）、`explanationJa`（任意） |
| `write` | 韓国語で書く | `questionJa`（必須）、`answers`（必須。韓国語。先頭が模範解答で、2つ目以降が別解）、`explanationJa`（任意） |
| `find` | 本文の中から探して押す | `questionJa`（必須）、`answer`（必須。本文の中の語句を、空白で区切ったまとまりのまま。メニューなら品名）、`findIn`（下の説明）、`explanationJa`（任意） |

- `questionJa`（問題文）と `explanationJa`（答えた後の説明）は日本語です。本文の語句を示すために、ハングルを入れてかまいません。
- `choice` の選択肢は、日本語なら `{ "textJa": "…", "correct": true }`、韓国語なら `{ "korean": "…", "pronunciation": "…", "japanese": "…", "correct": false }` の形にします（1つの選択肢にどちらか一方）。
- 空白・句読点・全角半角の違いは、判定のときにプログラムが吸収します（書く問題）。

### 25-3. 問題文の韓国語と、答えを探す場所

どの種類にも `questionKorean`（任意）を、`find` には `findIn` を書けます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `questionKorean` | 任意 | オブジェクト | 問題文の韓国語（例：`오늘의 추천 메뉴는 뭐예요?`）。25-1 の本文の1文と同じ形（`korean`・`pronunciation`・`japanese`・`glosses`）。問題文（`questionJa`）の下に出し、読み上げと単語のタップができます。訳（`japanese`）は、設定にかかわらず「タップで表示」です |
| `findIn` | `find` で、メニューと本文（`lines`）の両方がある読み物では必須 | キー | 答えがある場所。`"menu"`（メニューの品名）か `"lines"`（本文）。問題の間は、この場所の言葉だけを押せます。片方しかない読み物では省略でき、その場所になります |

- 韓国語の質問は `questionJa` に入れず、`questionKorean` に書きます。`questionJa` には、何をするか（例：「質問の答えを選ぼう」）を書きます。

### 25-4. 書くときの目安

- 最初は **3〜5文** くらいの短い文章にし、章が進むにつれて長くします。
- 問題は1つの読み物に **2〜4問**。答えが本文の中で見つけられるものにします。
- 知らない単語の量は 21-3 の目安に従います。

## 26. メニュー（GAME_SPEC 4-4）

店のメニューです。読み物（`style: "menu"`）と注文（27章）で同じメニューを使います。ゲームの画面に出す品名・値段で作ります。品名・読み・意味は単語の教材から出すので、品物ごとに単語の教材を作ってください。

見せ方は、実際の店に合わせて品物ごとに選びます（GAME_SPEC 4-4）。

- **文字のメニュー（메뉴판。`"display": "board"`）**：品名と値段だけを1行ずつ並べます。絵は出しません。カフェなら飲み物。
- **ショーケース（쇼케이스。`"display": "showcase"`）**：品物の絵（10-14）と、品名・値段の札を並べます。カフェならケーキやパン。
- 画面では、文字のメニューを上、ショーケースを下に出します。どちらも書いた順に並びます。分類の見出し（커피・차 など）は出しません。
- 品名の日本語は、注文の画面では出しません（品名を押すと意味が出ます）。読み物では、問題にすべて答えるまで出しません。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `menu_番号`（3章） |
| `location` | 必須 | キー | どの施設のメニューか（10-3） |
| `titleJa` | 必須 | 文字列 | 題（例：「カフェのメニュー」）。ハングルは入れない |
| `currency` | 必須 | オブジェクト | 値段の単位。`korean`（例：`원`）と `pronunciation`（例：`ウォン`）。値段は「4,500원」の形で出す |
| `items` | 必須 | 配列（1〜12個） | 品物（下の表）。画面には書いた順に並ぶ |
| `reviewed`・`notes` | | | 5章 |

`items` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `key` | 必須 | キー | 品物のキー（英小文字。メニューの中で重ねない。注文の記録に使う）。ふつうは絵のキーと同じにする |
| `display` | 必須 | キー | `"board"`（文字のメニュー）か `"showcase"`（ショーケース） |
| `vocab` | 必須 | 文字列 | 品名の単語のID。注文では、単語の別表記（`alternatives`）も正解にする |
| `price` | 必須 | 整数（0以上） | 値段（例：`4500`）。カンマは入れない |
| `pricePronunciation` | 必須 | 文字列 | 値段の読み。単位まで含めて区切りなしで書く（例：4,500원 → `サチョノベグォン`） |
| `image` | `showcase` なら必須 | キー | 品物の絵（10-14）。`board` の品物には書かない。同じ絵を2つの品物に使わない |
| `counter` | 必須 | 文字列 | 数え方の単位（韓国語。例：飲み物は `잔`、食べ物は `개`）。注文の数（27章）と合わせる |
| `reply` | 必須 | 配列（1個以上） | この品物を注文したときの店員のひとこと（台詞。8-2） |

## 27. 注文（書く・話す専用。GAME_SPEC 4-4）

メニューを見ながら、好きなものを韓国語で注文する場面です。選択肢は出さず、書くか話すかで答えます。イベントの `order` の段階で使い、その後も施設の画面から何度でも注文し直せます。経験値は、初めて注文できたときだけ付きます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `order_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章の注文か |
| `location` | 必須 | キー | 施設（10-3）。メニューの施設と同じにする |
| `character` | 必須 | キー | 注文を受ける人（10-4） |
| `menu` | 必須 | 文字列 | メニューのID（26章） |
| `task` | 必須 | 文字列 | 言うこと（日本語。例：「メニューから好きなものを1つ注文しよう」）。ハングルは入れない |
| `lines` | 必須 | 配列（1個以上） | 注文の前の台詞（8-2） |
| `counts` | 必須 | 配列（1個以上） | 言える数（下の表） |
| `endings` | 必須 | 配列（1個以上） | 注文の終わりの言い方（下の表） |
| `modifiers` | 任意 | 配列（1個以上） | 品物の前に付けてよい言葉（下の表） |
| `closing` | 必須 | 配列（1個以上） | 注文を受けた後の締めの台詞 |
| `notOnMenu` | 必須 | 配列（1個以上） | メニューにない品物を頼んだときの台詞（例：죄송합니다. 그건 없어요.） |
| `unclear` | 必須 | 配列（1個以上） | 言い方が分からないときの台詞（例：네? 다시 한번 말씀해 주시겠어요?） |
| `counterNoteJa` | 任意 | 文字列 | 数え方の単位が品物と合わないとき（例：`아메리카노 한 개 주세요`）に出す注意。ハングルを入れてよい |
| `reviewed`・`notes` | | | 5章 |

`counts` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 数の言い方（例：`한 잔`、`두 개`、`하나`） |
| `pronunciation` | 必須 | 文字列 | 読み（4章。品名の後に続けたときの読み） |
| `number` | 必須 | 整数（1〜99） | 数 |
| `counter` | 任意 | 文字列 | 数え方の単位（例：`잔`）。メニューの品物のどれかの単位にする。省略したら、どの品物にも使える（`하나` など） |
| `confirm` | 必須 | 配列（1個以上） | この数で注文されたときの、数を確かめる台詞（例：한 잔이요.） |

`endings` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 言い方（例：`주세요`） |
| `pronunciation` | `attached` でなければ必須 | 文字列 | 読み（前の語に続けたときの読み。例：`ジュセヨ`） |
| `attached` | 任意 | true / false | `true` なら、前の語にくっつける言い方（例：`아메리카노요` の `요`、`한 잔이요` の `이요`）。読みは書かない。答えの例には使わない |

- くっつけない言い方（`주세요` など）を1つ以上入れます（答えの例に使うため）。

`modifiers` の各要素：`korean`（必須）、`pronunciation`（必須）、`counter`（任意。この数え方の品物にだけ付けられる。例：`아이스` は `잔` の品物だけ）。

### 27-1. 判定のしかた（プログラムが決めること）

- 正解にする形：**［前に付けてよい言葉］＋ 品名 ＋［数］＋ 終わりの言い方**（［ ］はなくてもよい）。例：`아메리카노 주세요`、`아이스 아메리카노 두 잔 주세요`、`치즈케이크 하나요`。
- 品名は、メニューの品物の単語の見出し語と別表記（`alternatives`）を認めます。空白・句読点・全角半角の違いは吸収します。話して答えたときは、数字（`1잔`）も認めます。
- 数の単位が品物と合わないとき（`아메리카노 한 개`）は、通じたものとして進め、`counterNoteJa` の注意を出します。
- 1回に注文できるのは1品です（Phase 3）。
- 店員の反応：数を言ったときはその数の `confirm` → 品物の `reply` → `closing` の順に出します。メニューにない品物は `notOnMenu`、形が分からないときは `unclear` を出して、もう一度答えてもらいます。
- 書くのも話すのも難しいときは、「答えの例を見る」で進めます。答えの例は、品物（最初の品物）＋その単位の最初の数＋くっつけない最初の言い方で作ります（読みは、それぞれの読みをつなぎます）。
- 店員の台詞は、すべて教材に書いた文を使います（プログラムで韓国語を組み立てません）。
- 終わりの言い方は、いちばん長く一致したものだけを使います（`주세요` を `주세`＋`요` と分けません）。数だけで品名がない言い方（`한 잔 주세요`）は `unclear` です。
- 「答えの例を見る」から注文したときは進めますが、注文できた記録と経験値は付けません。

## 28. 実績（GAME_SPEC 7-2・7-3。Phase 4）

実績は開発側のデータ（`src/data/achievements/`）です。韓国語は入れません。案は Claude Code が作り、教材担当が文と数値を確かめて `reviewed: true` にします（直したいときは、開発者に伝えてください）。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `achievement_001` の形。後から変えない（セーブデータが達成した記録に使う） |
| `titleJa` | 必須 | 文字列 | 実績の名前（例：「はじめの一歩」）。ハングルは入れない |
| `descriptionJa` | 必須 | 文字列 | 達成の条件の説明（例：「単語を5語覚える」）。ハングルは入れない |
| `condition` | 必須 | オブジェクト | `{ "type": 条件の種類, "target": 数 }`。数が `target` 以上になったら達成（28-1） |
| `coins` | 必須 | 整数（0以上） | 達成したときにもらえるコイン |
| `reviewed` | 必須 | 真偽値 | 教材担当が確かめたか |
| `notes` | 任意 | 文字列 | メモ |

### 28-1. 条件の種類（`condition.type`）

| type | 数えるもの |
|---|---|
| `wordsLearned` | 覚えた単語の数（図鑑の「覚えた」） |
| `wordsSeen` | 見かけた単語の数（言葉を押して「覚える」を押したもの） |
| `chapterCleared` | その章のイベントをすべて終えた（`target` は章の番号） |
| `chapterTestsPassed` | 合格した章末テストの数 |
| `hangulLessonsPassed` | 合格したハングルのレッスンの数 |
| `reviewCorrect` | 今日の復習で正解した回数 |
| `drillItemsCorrect` | 正解した基礎ドリルの問題の数 |
| `listeningCorrect` | 正解したリスニングの問題の数 |
| `readingsCorrect` | 正解した読み物の問題の数 |
| `itemsOrdered` | 注文できた品物の種類の数 |
| `storiesSeen` | 見たおはなしの数 |
| `level` | レベル |

- 達成は一度だけで、取り消されません。新しい実績を足すと、すでに条件を満たしているプレイヤーは、次に遊んだときに達成します。
- 実績のほかのコイン（イベント・章・章末テスト）と、レベルの表・スタンプの節目は `src/data/game/balance.json` の `coins`・`levels`・`stampMilestones` です（開発側のデータ）。

## 29. 家具・小物（GAME_SPEC 6-3・7-3。Phase 4）

家具は開発側のデータ（`src/data/furniture/`）です。自宅の「部屋を飾る」で、カタログでコインを使って買い、部屋の決まった場所に置きます。節目専用の家具は、カタログでは売らず、スタンプの節目でもらえます。一覧と絵の決まりは docs/PHASE4_HOME_PLAN.md、絵の指示文は docs/ART_GUIDE.md 4-5 にあります。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `furniture_001` の形。後から変えない（セーブデータが持ち物と置き場所に使う） |
| `nameJa` | 必須 | 文字列 | 家具の名前。ハングルは入れない |
| `slot` | 必須 | 文字列 | 置く場所（29-1 の場所のID） |
| `price` | 必須 | 整数か null | 値段（コイン、1以上）。節目専用なら `null` |
| `level` | 必須 | 整数か null | カタログで買えるようになるレベル（1以上）。節目専用なら `null` |
| `milestone` | 必須 | 整数か null | 節目専用なら、もらえる節目（スタンプを集めた合計の数。`balance.json` の `stampMilestones` の `days`）。カタログで売るなら `null` |
| `image` | 必須 | 文字列 | 絵のキー（英小文字・数字・`_`）。元の画像は `fur_キー`（例：`wall_clock` → `fur_wall_clock.png`）。絵がまだなければ、ゲームでは仮の絵を出す |
| `vocab` | 必須 | 文字列か null | 韓国語の名前（単語ID）。押すと意味が出て、「覚える」で見かけた単語に入る。まだなければ `null` |
| `reviewed` | 必須 | 真偽値 | 名前・値段・レベルを確かめたか |
| `notes` | 任意 | 文字列 | メモ |

- 1か所に置けるのは1つだけです。買ったとき・もらったときに、その場所が空いていれば、そこに置きます（空いていなければ持ち物に入り、「飾る」で入れかえられます）。
- 同じ単語を、いくつかの家具の `vocab` に使えます（例：観葉植物と鉢植えの 화분）。

### 29-1. 部屋の場所（`balance.json` の `room`）

部屋の場所は `src/data/game/balance.json` の `room.slots` です（開発側のデータ）。位置と大きさは、部屋の絵の幅・高さに対する割合（%）です。

| 項目 | 意味 |
|---|---|
| `movedInAfter` | このイベントを終えるまでは「引っ越したばかり」：自宅の背景を `home_moving` にし、「部屋を飾る」を出さない |
| `slots[].id` | 場所のID（`wall_left` など）。後から変えない（セーブデータが置き場所に使う） |
| `slots[].nameJa` | 場所の名前（例：「壁（左）」） |
| `slots[].x`・`y`・`w`・`h` | 枠の左端・上端・幅・高さ（%）。絵の外に出ないように |
| `slots[].align` | 家具の絵をそろえる位置。`bottom`：床に置くもの（枠の下の辺、左右は中央）、`center`：壁・ラグ（枠の中央） |
| `slots[].layer` | 重なりの順（小さいほど奥） |
