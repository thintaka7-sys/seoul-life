# 教材JSONの書き方

「서울에서 살기」の教材（単語・文法・会話）と、イベント（単語を覚える段階と会話の順番）を JSON ファイルで作るための説明です。
教材を作るチャットに、このファイルと docs/CONTENT_STYLE.md をそのまま渡して使えます。

- 韓国語の書き方・カタカナの読み・正解の決め方は **docs/CONTENT_STYLE.md**（表記ルール）に従ってください。
- 教材を作る流れと確認の手順は GAME_SPEC.md 11-4 を参照してください。
- この説明と見本は、プログラムの検証ルールと一致しているかを自動テストで確かめています（`src/data/contentFormatDoc.test.ts`）。

---

## 1. ファイルの置き場所

| 種類 | フォルダ | ファイル名の例 |
|---|---|---|
| 単語 | `src/data/vocabulary/` | `ch01.json`、`ch03_cafe.json` |
| 文法 | `src/data/grammar/` | `ch02.json` |
| 会話 | `src/data/scenarios/` | `ch03_cafe.json` |
| イベント | `src/data/events/` | `day1.json`、`ch04.json` |

- フォルダに `.json` ファイルを置くと、自動で読み込まれます。ファイル名は自由です。章ごとに分けるのがおすすめです（`ch01.json`、`ch02.json` …）。
- 1つのファイルには、1種類のデータの**配列**（`[ … ]`）を入れます。単語と文法を同じファイルに混ぜないでください。
- 教材を渡すときは、`content-inbox/phase番号/` に同じフォルダ分けで置いてもらえれば、開発側で `src/data/` に移します。

---

## 2. JSONを書くときの決まり

- 文字コードは UTF-8 にします。
- 文字列は `"ダブルクォート"` で囲みます。シングルクォートは使えません。
- 最後の項目の後ろにカンマを付けません。JSON にはコメントも書けません。メモは `notes` 項目に書いてください。
- `true` / `false` と数字は、引用符で囲みません（`"level": 1`。`"level": "1"` は誤り）。
- 表にない項目名を書くとエラーになります。綴りの間違い（例：`pronounciation`）を見つけるためです。
- ハングルは普通に入力した文字で書きます。字母（ㅋ ㅓ ㅍ ㅣ）を並べた形にはしません。プログラムはUnicode正規化（NFC）された文字かどうかを確かめます。

---

## 3. ID の決まり

- **一度ゲームに入れたIDは、後から変えたり使い回したりしません。** セーブデータと学習記録がIDで教材を参照しているためです。不要になった教材は削除してよいですが、そのIDは二度と使いません。
- 単語・文法・会話のIDは、3つの種類を通して重複できません。別のファイルにあっても重複はエラーになります。
- 番号は3桁以上にします（`001`、`002` … `999`、`1000`）。
- **900番台（`vocab_901` など）は、プログラムの仮データ用に予約しています。** 本番の教材では使わないでください。

| 種類 | 形式 | 例 |
|---|---|---|
| 単語 | `vocab_番号` | `vocab_001` |
| 文法 | `grammar_番号` | `grammar_001` |
| 会話 | `英小文字の名前_番号`（施設ID＋番号を推奨） | `cafe_001`、`convenience_store_001` |
| イベント | `event_番号` | `event_001` |

## 4. 読み（カタカナのフリガナ）の決まり

韓国語の文には、カタカナの読みを付けます。ゲームでは、韓国語の上に**区切り（空白）ごと**にフリガナとして表示します。

- **韓国語と同じ位置で、半角スペースを1つ入れて区切ります。** 区切りの数が韓国語と違うとエラーになります。
  - 例：`아메리카노 한 잔 주세요.` → `アメリカノ ハン ジャン ジュセヨ`（どちらも4つ）
  - 韓国語の句読点は、前の語といっしょに1つの区切りとして数えます（`안녕하세요.` で1つ）。
- 読みに使える文字は、**カタカナ（ー を含む）と半角スペースだけ**です。句読点・ひらがな・全角スペースは入れません。先頭と末尾に空白を入れず、空白を2つ続けません。
- カタカナの書き方（連音化・濃音の「ッ」など）は docs/CONTENT_STYLE.md の1章に従います。

| 読みの項目 | 付ける場所 |
|---|---|
| `pronunciation` | 単語の見出し語、文法の例文、会話の台詞、会話の選択肢 |
| `examplePronunciation` | 単語の例文 |

書く問題の正解（`freeAnswer.answers`）は、プレイヤーが書く答えなので読みを付けません。

## 5. 共通の項目

すべての単語・文法・会話に付けます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | 一意のID（3章） |
| `reviewed` | 必須 | true / false | 韓国語を確認済みか。作ったときは `false` にし、別のAIや韓国語母語話者の確認が済んだら `true` にする |
| `notes` | 任意 | 文字列 | 確認者のメモ（確認した人・日付・気になった点など） |

---

## 6. 単語

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 韓国語（見出し語）。正解判定では、これが模範解答になる |
| `alternatives` | 任意 | 文字列の配列 | 正解として認める別表記（例：`짜장면` に対する `자장면`）。1個以上入れる。`korean` と同じものは入れない |
| `pronunciation` | 必須 | 文字列 | 見出し語の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `partOfSpeech` | 必須 | キー | 品詞（9-1のキー一覧から選ぶ） |
| `category` | 必須 | キー | カテゴリ（9-2のキー一覧から選ぶ） |
| `level` | 必須 | 整数（1以上） | 難しさ。1がいちばんやさしい |
| `example` | 任意 | 文字列 | 例文（韓国語） |
| `examplePronunciation` | 任意 | 文字列 | 例文の読み（4章） |
| `exampleJapanese` | 任意 | 文字列 | 例文の日本語訳 |

- 例文の3項目（`example`・`examplePronunciation`・`exampleJapanese`）は、**3つそろえて書くか、3つとも省きます。**
- 空白の違い（分かち書き）と、句読点（. , ? !）、全角・半角の違いは、判定のときにプログラムが吸収します。そのため、こうした違いだけの別表記を `alternatives` に入れる必要はありません。
- 意味は同じでも別の単語（類義語）は、原則として `alternatives` に入れません。入れる場合は、`notes` に理由を書いてください。

---

## 7. 文法

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `title` | 必須 | 文字列 | 文法の名前（例：`이에요 / 예요`） |
| `level` | 必須 | 整数（1以上） | 難しさ |
| `explanation` | 必須 | 文字列 | 日本語での説明。初心者に分かる簡単な言葉で書く |
| `examples` | 必須 | 配列（1個以上） | 例文。各要素は下の表のとおり |

`examples` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 例文（韓国語） |
| `pronunciation` | 必須 | 文字列 | 例文の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |
| `alternatives` | 任意 | 文字列の配列 | 例文を答えさせる問題で、正解として認める別の言い方 |

GAME_SPEC 4-3 にある接続ルール・穴埋め問題・並べ替え問題の項目は、Phase 2 で追加します。項目を追加するときは、この説明も更新します。

## 8. 会話

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `chapter` | 必須 | 整数（1〜10） | 何章の会話か（GAME_SPEC 5章） |
| `location` | 必須 | キー | 会話する施設（9-3） |
| `character` | 必須 | キー | 会話の相手（9-4。`player` は使えない） |
| `lines` | 必須 | 配列（1個以上） | プレイヤーが答える前の台詞 |
| `choices` | 必須 | 配列（1個以上） | 選んで答えるときの選択肢。`"correct": true` を1つ以上入れる |
| `freeAnswer` | 任意 | オブジェクト | 書いて（話して）答えるときのお題と正解 |

`lines` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `speaker` | 必須 | キー | 話す人（9-4） |
| `korean` | 必須 | 文字列 | 台詞（韓国語） |
| `pronunciation` | 必須 | 文字列 | 台詞の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳 |

`choices` の各要素：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `korean` | 必須 | 文字列 | 選択肢（韓国語）。同じ会話の中で重複させない |
| `pronunciation` | 必須 | 文字列 | 選択肢の読み（4章） |
| `japanese` | 必須 | 文字列 | 日本語訳。間違えたときに「〜という意味です」と表示するのにも使う |
| `correct` | 必須 | true / false | 正解か。正解は複数あってもよい |

`freeAnswer`：

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `prompt` | 必須 | 文字列 | 日本語のお題（例：「コーヒーをください」） |
| `answers` | 必須 | 文字列の配列（1個以上） | 正解。**先頭が模範解答**で、2つ目以降が別解。自然な言い方が複数ある場合は、すべて入れる |

- 1つの会話データは「台詞 → プレイヤーの返事」の1往復です。会話を続けるときは、イベント（10章）で会話を順番に並べます。
- 丁寧語とタメ口の使い分けは docs/CONTENT_STYLE.md の2章に従います。

## 9. キーの一覧

### 9-1. 品詞（`partOfSpeech`）

| キー | 意味 | 例 |
|---|---|---|
| `noun` | 名詞 | 커피、학생 |
| `pronoun` | 代名詞 | 저、이거 |
| `numeral` | 数詞 | 하나、일 |
| `verb` | 動詞 | 가다、먹다 |
| `adjective` | 形容詞 | 좋다、맛있다 |
| `adverb` | 副詞 | 아주、같이 |
| `particle` | 助詞 | 은/는、을/를 |
| `determiner` | 冠形詞（連体詞） | 이、그、저 |
| `interjection` | 感嘆詞・返事 | 네、아니요 |
| `greeting` | あいさつ・お礼・お詫びの決まった表現 | 안녕하세요、감사합니다 |

|---|---|
| `greeting` | 挨拶 |
| `people` | 人 |
| `food` | 食べ物 |
| `drink` | 飲み物 |
| `number` | 数字 |
| `time` | 時間（曜日・日付を含む） |
| `place` | 場所（方向を含む） |
| `shopping` | 買い物 |
| `daily_life` | 日常生活 |
| `emotion` | 感情 |
| `verb` | 動詞 |
| `adjective` | 形容詞 |

### 9-3. 施設ID（会話・イベントの `location`）

| キー | 施設 |
|---|---|
| `home` | 自宅 |
| `cafe` | カフェ |
| `convenience_store` | コンビニ |
| `bookstore` | 本屋 |
| `park` | 公園 |
| `station` | 駅 |

### 9-4. キャラクターID・話者ID（会話の `character` と `speaker`）

| キー | 人物 | `character` に使える | `speaker` に使える |
|---|---|---|---|
| `friend` | キャラクターA：近所の友人 | ○ | ○ |
| `cafe_staff` | キャラクターB：カフェの店員 | ○ | ○ |
| `neighbor` | キャラクターC：近所の住人 | ○ | ○ |
| `player` | 主人公（プレイヤー） | × | ○ |

- キャラクターの名前・口調は Phase 3 で決めます。IDは役割を表す名前のまま変えません。
- 施設・キャラクターを追加したいときは、教材を作る前に開発者に伝えてください。プログラム側のデータ（`src/data/locations/`、`src/data/characters/`）への追加が必要です。

### 9-5. イベントの段階の種類（`steps` の `type`）

| キー | 意味 | ほかの項目 |
|---|---|---|
| `message` | 日本語の案内文を表示する（場面の説明、次にすることなど） | `textJa`（必須） |
| `learn` | 単語カード・文法カードで覚える。覚えた単語は図鑑に入る | `vocabulary`・`grammar`（IDの配列。どちらか一方に1つ以上） |
| `conversation` | 会話を1つ行う | `id`（会話ID。必須） |
| `dictionary` | 図鑑を開いて見返す | `textJa`（必須。図鑑の上に出す案内） |
| `dayEnd` | 1日の終わりの画面を出す | `textJa`（必須） |

## 10. イベント

イベントは「どの施設で、何を、どの順に行うか」を決めるデータです。教材とあわせて下書きしてください。プレイヤーは、前提のイベントを終えた後に、その施設で「`actionJa`」のボタンを押してイベントを始めます。

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `id` | 必須 | 文字列 | `event_番号`（3章） |
| `chapter` | 必須 | 整数（1〜10） | 何章のイベントか。フリガナをいつも出すかどうかの判定にも使う |
| `location` | 必須 | キー | イベントが起きる施設（9-3） |
| `requires` | 必須 | 文字列の配列 | 先に終えておくイベントのID。最初のイベントは `[]` |
| `objectiveJa` | 必須 | 文字列 | 目標として画面の上に出す文（例：「カフェで注文してみよう」） |
| `actionJa` | 必須 | 文字列 | 施設の画面に出す、イベントを始めるボタンの文字（例：「カウンターへ行く」） |
| `steps` | 必須 | 配列（1個以上） | 段階を順番に並べる（9-5） |
| `notes` | 任意 | 文字列 | メモ |

**決まり**
- **日本語の文（`objectiveJa`・`actionJa`・`textJa`）には、ハングルを入れません。** 韓国語を見せたいときは、単語・文法・会話の教材として作り、`learn` や `conversation` で使います。
- `conversation` で使う会話は、イベントと同じ施設の会話にします。1つの会話は、1つのイベントでしか使えません。
- 単語は、その単語が初めて出てくる会話より前の `learn` で覚えるようにします。1度に覚える単語は、5〜7語くらいまでを目安にします。
- `requires` に書いたイベントが存在しない場合や、前提が循環している場合はエラーになります。
- 同じ施設で始められるイベントが複数あるときは、ファイルの中で先に書いたものから始まります。

## 12. 書いたファイルを確かめる

ファイルを置いたら、プロジェクトのフォルダで次を実行します。

```
npm run test
```

- 問題がなければ、すべてのテストが通ります。
- 問題があれば、`data/ の実データ > 検証で問題が1件もない` のテストが失敗し、`ファイル名 / 何番目 / ID / 項目: 理由` の形で一覧が表示されます。
- 問題のあるデータは、ゲームでは読み込まれません（ゲームは止まらず、そのデータだけ除外されます）。開発中は、タイトル画面にも件数が表示されます。
